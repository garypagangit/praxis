# SEC-LoRD Relationship-Evidence Slice Leakage Audit — Ready

**Date:** 2026-05-17
**Owner:** Gary Pagan
**Status:** Pre-registered; not yet run.
**Predecessor:** `SEC_LORD_RELATIONSHIP_EVIDENCE_MODEL_GATE_20260517.md` (8B PASS, +0.274 absolute)
**Successor (conditional):** ablation gate; thesis section.

## Why this gate exists

The 8B PASS at +0.274 absolute rests on a 106-row slice selected by a label-free retrieval-ranking criterion: "exactly one option had strong lexical support from retrieved evidence." That criterion is asserted to be independent of `expected_output`. This audit demonstrates it.

The risk being audited: the slice criterion may co-vary with question difficulty. If the questions where retrieval surfaces a single strong candidate are systematically easier than the rest of the benchmark, then the +0.274 lift is partly a selection artifact, not pure retrieval lift. This is the load-bearing methodological claim of the entire result; it must be defended explicitly before the thesis section is written.

## Audit components

Four components. Each is independently necessary. All four must pass.

### A1 — Pipeline isolation of `expected_output`

A static-analysis check that no code path used to construct the 106-row slice has access to the label column.

Required artifact: a short script (`scripts/audit_slice_label_isolation.py`) that:

- Loads the retrieval-ranking module exactly as it was called during slice selection.
- Asserts the module's input schema does not contain `expected_output` or any column derived from it.
- Runs the ranker on a copy of the CTI-MCQ dataset with the label column physically removed and verifies the resulting slice is byte-identical to the slice used in the 8B PASS.

Pass condition: slice hash matches. Fail condition: any mismatch — re-derive the slice from the no-label dataset and use *that* as the canonical slice going forward.

### A2 — Complement-slice vanilla check

The audit that matters most.

Define the complement slice: every CTI-MCQ row that was *not* selected into the 106-row evidence-addressable slice. Run the 8B vanilla arm on the complement.

Pre-registered interpretations:

| Complement vanilla accuracy | Interpretation |
|----------|----------------|
| within 0.03 of 0.642 | Slice selection is balanced on difficulty. The +0.274 lift is interpretable as retrieval lift. |
| 0.03 to 0.10 below 0.642 | Slice is somewhat easier than the complement. Report adjusted lift = (relationship − complement-vanilla), not (relationship − slice-vanilla), in all headline claims. |
| more than 0.10 below 0.642 | Slice is materially easier than the complement. The +0.274 figure cannot stand as published. Either redesign the slice criterion or reframe the contribution as protocol-conditional. |
| at or above 0.642 | Slice is *harder* than the complement (unexpected). The +0.274 lift is actually conservative; report this finding explicitly. |

Pass condition: top row or bottom row. Soft pass: second row, with corrected headline number. Fail: third row.

### A3 — Slice-selection determinism

The 106-row slice was generated by a retrieval ranker. Rerunning the ranker must produce the same 106 rows.

Required check: rerun the slice-selection pipeline three times with three different random seeds (if any randomness is present in retrieval) and report the symmetric difference between resulting slices.

Pass condition: symmetric difference is 0 (deterministic) or under 5 rows out of 106 (negligible). Fail condition: symmetric difference exceeds 5 — the slice is not a stable unit of evaluation and the 8B PASS must be reported as conditional on the specific slice seed.

### A4 — Threshold-was-set-before-scoring check

Documentation check, not a run.

Required artifact: a timestamped commit or log entry showing the "exactly one option has strong lexical support" criterion was pinned before the 8B accuracy numbers were computed. Git blame on the relevant code, plus the run log timestamp, is sufficient.

Pass condition: criterion code commit timestamp precedes the first 8B run timestamp. Fail condition: ordering is unclear or reversed — the 106-row slice must be treated as exploratory and the gate result re-run on a pre-registered alternative slice.

## Required result artifacts

A single audit writeup, `SEC_LORD_RELATIONSHIP_EVIDENCE_SLICE_AUDIT_<DATE>.md`, must record:

- A1: slice hash match (yes/no), any mismatched-row IDs.
- A2: complement vanilla accuracy, complement row count, interpretation row (1/2/3/4), adjusted headline lift if applicable.
- A3: per-seed slice hash, symmetric difference count.
- A4: criterion commit hash, criterion commit timestamp, first 8B run timestamp, ordering verdict.
- Overall audit verdict: PASS, SOFT PASS (adjusted lift), or FAIL with reason.

## Cloud-run handoff

A2 requires one cloud run on the GPU instance: 8B vanilla arm on the complement slice. Expected size: roughly the CTI-MCQ benchmark size minus 106 rows; if the parent benchmark is the 500-row CTI-MCQ set referenced in `SEC_LORD_RETRIEVED_EVIDENCE_GATE_READY_20260514.md`, the complement is approximately 394 rows. Wall-clock expected under 30 minutes including instance start/stop.

A1, A3, A4 are local-only and run on the diagnostic environment.

Sequence: run A1, A3, A4 locally first. If any of those fail, abort A2 — the audit is already failed and the cloud run is wasted budget. If A1/A3/A4 all pass, then run A2.

## Pre-registered failure-mode interpretations

- **All four pass:** Slice methodology is defensible. The +0.274 headline number stands. Proceed to ablation gate.
- **A2 soft pass (row 2):** Slice is mildly easier than complement. The headline becomes the adjusted lift. Proceed, but every thesis claim must use the adjusted number.
- **A2 hard fail (row 3):** Slice is materially easier than complement. The contribution must be reframed as protocol-conditional ("under the evidence-addressable slicing protocol, retrieval lift is X") rather than as a general claim. Consider redesigning the slice.
- **A1 or A4 fail:** The audit cannot certify the slice. Re-derive on a no-label-confirmed pipeline and re-run the 8B gate before any further work.
- **A3 fail:** The slice is unstable. Report all results as conditional on a specific slice draw and either pin a slice version or report results aggregated across slice draws.

## Stop conditions

- A2 complement-vanilla accuracy below 0.30 or above 0.95. (Suggests benchmark is degenerate on the complement; rethink the audit.)
- A1 surfaces any pipeline branch that touches `expected_output`. Stop everything, fix the pipeline, re-run the 8B gate, and re-run this audit.

## Out of scope for this gate

- Cross-model leakage. The A2 check is 8B vanilla only; the 3B audit happens within the cross-model gate, not here.
- Retrieval-corpus leakage (whether ATT&CK STIX text overlaps with CTI-MCQ text in ways that pre-bake answers). That is a separate concern handled in the ablation gate via the random-facts arm.
- Benchmark-level leakage (whether CTI-MCQ overlaps with the model's pretraining corpus). Out of scope; standard for any retrieval-augmented evaluation.
