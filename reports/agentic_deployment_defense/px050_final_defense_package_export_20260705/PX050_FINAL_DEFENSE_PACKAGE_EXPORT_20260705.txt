What This Proves
1. A deterministic package-install boundary verifier can block the measured invalid PyPI/NPM install strings and dry-run tool-call arguments before execution.
2. The controller/extractor repair is necessary for noisy agent/model output: it selects a target-matching install command and routes misses to review.
3. Registry-only checking is not enough on adversarial or mixed command distributions; PX-050T and PX-050U/V show registry-only invalid allows where the hardened path allowed none.
4. The policy layer can preserve full valid-action utility while retaining zero invalid escapes on the 288-row live-agent corpus.
5. Observable provenance fields are sufficient in this corpus to trace and alert on untrusted tool-call arguments without hidden chain-of-thought access.

What This Does Not Prove
- It does not prove broad coding-agent safety.
- It does not execute package managers or evaluate post-install behavior.
- It does not detect malicious packages that really exist in a registry.
- It does not cover arbitrary shell commands outside the modeled package-install boundary.
- It does not claim raw-output third-model replication; the raw and strict StarCoder2 gates failed.
- It does not monitor hidden model reasoning.
