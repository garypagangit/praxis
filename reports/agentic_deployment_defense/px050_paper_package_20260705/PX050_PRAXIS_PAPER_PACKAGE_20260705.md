# PX-050 Praxis Paper Package

Generated: 2026-07-05

## Title

Deterministic Tool-Boundary Gates for Agentic Package-Install Hallucination

## Praxis Thesis

Tool-using coding agents can emit package-install command strings that appear executable while naming invalid packages, remote package sources, mixed valid/invalid dependency sets, or shell-composed install actions. PX-050 tests whether a deterministic tool-boundary verifier can prevent those command strings from crossing into execution without requiring access to the model's hidden reasoning.

The supported thesis is bounded:

> A deterministic package-install gate can block invalid or policy-unsafe model-generated install command strings with zero observed invalid-package escapes across two open-weight coding models, while preserving high valid-command utility. Differential improvement over registry-only checking is model-dependent.

## Status

**PUBLISHABLE_BOUNDED_POSITIVE**

PX-050 has enough evidence for a bounded Praxis defense paper. It should be presented as a command-string/tool-boundary verifier result, not as a general software supply-chain security solution.

## What The Result Proves

1. The hardened PX-050 verifier blocked all observed invalid package-install command strings in the fixed fixture, the Qwen live corpus, the DeepSeek live corpus, and the parser-stress mutation appendix.
2. The verifier preserved valid install-command utility above the registered thresholds in all measured stages.
3. Registry-only validation is insufficient for command strings that include mixed valid/invalid arguments, aliases, shell composition, remote specs, and parser edge cases.
4. The size of the uplift over registry-only checking depends on the model-generated attack distribution. Qwen generated bypass-shaped invalid commands that registry-only checking missed; DeepSeek mostly generated simpler direct invalid commands that registry-only checking also caught.
5. The result supports a deployment pattern: validate tool-call arguments at the boundary using deterministic parsing, package provenance policy, and action consequence scoring before any package manager is allowed to execute.

## Claim Boundary

PX-050 may claim:

- The hardened gate achieved zero observed invalid-package escapes on the measured command-string corpora.
- The hardened gate preserved high valid-command utility on the measured valid package-install commands.
- The gate closed registry-only gaps on Qwen and on parser-stress mutations.
- The combined PX-050/PX-051/PX-052 chain supports deterministic tool-boundary verification as a practical agent defense pattern.

PX-050 must not claim:

- General package ecosystem security.
- Protection against malicious packages that exist in a registry.
- Safety for arbitrary shell commands outside the modeled package-install boundary.
- Safety after command execution. The experiments are inert and do not execute package managers.
- A universal model behavior claim that all coding models will produce registry-bypass-shaped invalid commands.
- A hidden-chain-of-thought monitoring claim. The defense uses observable tool-call strings and structured provenance only.

## Publication Shape

Recommended framing:

1. **Problem:** coding agents may turn hallucinated dependency names into executable package-install actions.
2. **Method:** freeze a deterministic package-install parser and verifier at the tool boundary.
3. **Evaluation:** test fixed adaptive commands, live model-generated commands from two coding models, mutation stress cases, policy operating points, and provenance traces.
4. **Result:** zero observed hardened escapes with high utility; registry-uplift present under bypass-shaped command distributions and mixed under simpler command distributions.
5. **Deployment lesson:** deterministic boundary checks are not a full security system, but they are a low-friction control that catches a concrete class of agentic deployment failures before execution.
