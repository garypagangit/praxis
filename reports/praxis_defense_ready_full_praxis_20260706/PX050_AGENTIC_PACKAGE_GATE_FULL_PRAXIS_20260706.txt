Abstract of Praxis
This praxis evaluates deterministic package-install gates for model-generated PyPI/NPM install strings and dry-run live-agent tool-call arguments. Across fixed, live-model, parser-stress, controller/extractor, crafted stress, and two-model dry-run live-agent gates, the hardened path produced zero observed invalid package escapes under the defended corpora. The final 288-row Qwen/DeepSeek live-agent corpus had raw unsafe rate 0.9453, controller recovery 0.9757, registry-only invalid allows 20, hardened invalid allows 0, and valid allow 1.0000.

CHAPTER 1: INTRODUCTION

1.1 Background
Deterministic Tool-Boundary Gates for Agentic Package-Install Hallucination is part of the Praxis Research portfolio, a future-work-to-experiment program for AI/ML and cybersecurity engineering. The portfolio standard is evidence-first: a result is promoted only when it has a defined objective, a reproducible artifact trail, a measured gate, and a written claim boundary.

1.2 Research Motivation
Agentic coding systems can turn model hallucinations into executable tool calls. Package-install boundaries are a narrow but high-value deployment control point.

1.3 Problem Statement
Registry checks alone can miss policy-unsafe or malformed install actions, while overblocking valid installs would destroy utility.

1.4 Thesis Statement
Deterministic validation at the package-install tool boundary can block invalid or policy-unsafe model-generated install actions before execution while preserving useful valid installs under an observable, no-execution boundary.

1.5 Research Objectives
1. Evaluate hardened deterministic package-install verification.
2. Compare against registry-only validation.
3. Repair noisy model output with controller/extractor routing.
4. Validate on dry-run live-agent tool-call corpora without package-manager execution.

1.6 Research Questions and Hypotheses

----------------+---------------------------------------------------------------------------------------------------------------------------------------------------------------------------

RQ2 / H2 | Does hardened validation outperform registry-only checking on adversarial/mixed corpora? Hypothesis: Valid allow remains high, with final live-agent valid allow 1.0000.
RQ3 / H3 | Can controller/extractor repair preserve valid utility under noisy model output? Hypothesis: Controller/extractor target recovery exceeds 0.95 in deployment-shaped tests.
RQ4 / H4 | Does the boundary hold under dry-run live-agent tool calls? Hypothesis: Policy/provenance refreshes preserve utility and traceability.

3.9 Evaluation Metrics and Statistical Methods
Metrics:
- Invalid allow count = count(expected invalid row where hardened decision is allow).
- Invalid escape rate = invalid allow count / invalid rows.
- Valid allow rate = count(expected valid row where hardened decision is allow) / valid rows.
- Registry-only invalid allow count = expected invalid rows that a registry-only check would allow.
- Controller target recovery rate = rows where the controller/extractor selects a target-bearing install command / all rows.
- Review rate = rows routed to review / all rows.
- Provenance alert recall = expected alert rows flagged / expected alert rows.
- Clean false-positive rate = clean valid rows alerted / clean valid rows.
- Trace completeness = rows with complete observable lineage / all rows.

Verifier formalization:
- Let r be a dry-run model output or tool-call argument.
- Let c = extract(r) be the controller-selected install command.
- Let p = parse(c) return ecosystem, package targets, syntax flags, and parse status.
- Let e(p) be registry-existence evidence for the package targets.
- Let s(p) be deterministic policy safety, including remote source, shell-chain, malformed, no-target, and unsupported-manager checks.
- Hardened decision h(r) is allow only if parse succeeds, target packages are recoverable, registry evidence passes, and policy safety passes; otherwise h(r) is block or review.
- The defended safety property is empirical: for the measured corpora, count(expected invalid and h(r)=allow) = 0.

Zero-event statistics:
- Two-model live-agent corpus: 0 invalid allows over 128 invalid rows. Exact one-sided 95% upper bound is approximately 2.31%.
- Parser-stress corpus: 0 invalid escapes over 600 invalid rows. Exact one-sided 95% upper bound is approximately 0.50%.
- Controller adaptive stress: 0 invalid allows over 1,140 invalid rows. Exact one-sided 95% upper bound is approximately 0.26%.
- Defense wording must be "zero observed invalid allows" rather than "zero possible escapes."

4.5 Cross-Experiment Analysis
- Final live-agent corpus: 288 rows.
- Raw unsafe rate 0.9453 and controller recovery 0.9757.
- Registry-only invalid allows 20; hardened invalid allows 0.
- Valid allow 1.0000; provenance trace completeness 1.0000.
- The registry-only baseline fails mainly on remote-source style invalid commands, where a package name can appear registry-valid while the install action remains policy-unsafe.
- Hardened validation dominates registry-only validation on security while preserving the same observed valid utility in the final two-model corpus.
- The review-all baseline can eliminate invalid execution but sacrifices practical utility; PX-050's hardened policy is more deployable because it keeps review rate at 0.0243 in the policy refresh.
- The held-out StarCoder raw/strict failures are not ignored; they establish that raw model text is not the right deployment boundary. The controller/extractor repair is the defended deployed boundary.
