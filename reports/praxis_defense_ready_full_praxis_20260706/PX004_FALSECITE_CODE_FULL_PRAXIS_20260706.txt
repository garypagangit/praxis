A strict external verifier reaches 1.0000 accuracy and invalid recall on 80 locked claims. In audit and generation modes, model-only outputs trust fabricated citations at high rates, while metadata evidence and verifier guards reduce strict fabricated trust to 0.0000 under the tested conditions.

CHAPTER 1: INTRODUCTION

1.1 Background
FalseCite-Code External Verification for Software-Artifact Citation Poisoning is part of the Praxis Research portfolio, a future-work-to-experiment program for AI/ML and cybersecurity engineering. The portfolio standard is evidence-first: a result is promoted only when it has a defined objective, a reproducible artifact trail, a measured gate, and a written claim boundary.

1.2 Research Motivation
Software-artifact citations are operationally sensitive because trusting a fabricated version, repository, or tag can mislead code maintenance and dependency decisions.

1.3 Problem Statement
Language-model plausibility is not enough to determine whether a software artifact exists or whether a cited version/tag is real.

1.4 Thesis Statement
Code assistants can be induced to trust fabricated software-artifact citations, but external metadata verification can suppress this failure mode on a locked benchmark.

1.5 Research Objectives
1. Construct a balanced valid/fabricated artifact-citation benchmark.
2. Measure model trust in fabricated citations.
3. Evaluate deterministic external metadata verification.
4. Audit freshness and strict-holdout behavior.

1.6 Research Questions and Hypotheses
RQ / Hypothesis | Statement
----------------+----------------------------------------------------------------------------------------------------------------------------------------------------------------------
RQ1 / H1 | Do code models accept fabricated software-artifact citations? Hypothesis: Base model trust in fabricated citations is non-zero and operationally meaningful.
RQ2 / H2 | Can metadata evidence suppress fabricated trust? Hypothesis: External metadata verification reaches 1.0000 invalid recall on the locked benchmark.
RQ3 / H3 | Does a citation-aware verifier outperform trust-all and regex floors? Hypothesis: Verifier-guarded answers reduce fabricated trust to zero in tested prompt settings.
RQ4 / H4 | Does the verifier remain stable under freshness audit? Hypothesis: API freshness audit does not introduce verifier errors.

1.7 Scope of Research
80 locked software-artifact claims across PyPI, NPM, GitHub repositories, and GitHub tags.

1.8 Research Limitations
Not universal hallucination prevention, not general package-install safety, and not a claim across all code assistants.
