# Candidate 010: attack-aware forecasting qualification

Version Q1, September 14, 2026. Freeze this document and its source manifest before executing a pilot. This is a development qualification, not a confirmatory efficacy study. No HAI test outcomes may be scored in Q1.

## Research question and literature

RQ: Can a detector preserve evidence of a persistent sensor attack while recovering after legitimate changes, using only information available when each observation arrives? The prospective modification is a fixed commissioning reference plus separately updated operational context, with a bound on suspicious channels' admitted influence. That combination remains a candidate, not established novelty.

[Anand, Nguyen, and Pappas, Attack Detection using Time Series Foundation Models](https://arxiv.org/abs/2606.06347) supplies the first base experiment. Its published replay script uses TimesFM 2.5, a three-sensor linear oscillator, and an observer. Source inspection found a material distinction: the released script blends 80% predicted and 20% measured values after alarms, and enables that protection only at the known attack start. This historical oracle condition must be retained in exact reproduction and removed only in a separately named deployable comparator. Literal frozen context is another distinct comparator.

[Uray et al., Exploring Zero-Shot Foundation Models for Multivariate Time Series Anomaly Detection](https://arxiv.org/abs/2607.12454) motivates measuring late-episode detection: anomalous dynamics can become predictable. Neither persistence failure nor applying TimesFM to cyber data is new.

[Martinez Gil et al., Adaptive Conformal Anomaly Detection with Time Series Foundation Models for Signal Monitoring](https://arxiv.org/abs/2604.20122) supplies the public-data base: its W1ACAS implementation, one NAB series from its stated TSB-AD benchmark family, and Chronos Bolt Small, one of its evaluated models. A single-series rerun is an implementation reproduction; it is not replication of the paper's aggregate benchmark score.

Google's [TimesFM repository](https://github.com/google-research/timesfm) supplies the new multivariate model. TimesFM 3 weights have separate noncommercial, nonproduction terms; source code is Apache 2.0. [HAI](https://github.com/icsdataset/hai) is the potential later public cyber dataset, collected in an industrial testbed. Public benchmark pretraining exposure remains possible.

## Hypotheses and advance gates

QH1, implementation: the independent CPU implementation reproduces all 20 released linear replay trajectories, clean observer residuals, attack residuals, and alarm decisions to absolute/relative tolerance 1e-10. These outputs come from the model-based observer, not an FM. All source/data hash and chronology checks pass.

QH2, controlled persistence: on fixed synthetic step streams, the rolling last-value forecaster alarms at onset but has at most 10% alarm retention after the first 32 attacked observations; a frozen-reference detector retains at least 90%. At least 9 of the 10 predetermined seeds must satisfy both. The same numerical stream labeled as a benign change must yield identical detector outputs. This negative control establishes an identifiability limitation, not attack/benign discrimination. A permanently frozen detector's persistent benign alarms are reported as a failure to adapt.

QH3, original FM and calibration implementation: TimesFM 2.5 completes the published 20-trial replay experiment with finite forecasts/covariances, all 600 attack positions and 600 matched clean positions retained, and exact intervention accounting. Report the published script's historical oracle blending separately from alarm-only blending and literal freeze. No accuracy threshold is used to discard the experiment. W1ACAS plus Chronos Bolt Small completes the designated public NAB series, all assigned predictions and unscored boundary positions accounted for, and repeated same-input predictions agree within 1e-5. Preserve raw pointwise scores. Do not claim aggregate-paper replication.

QH4, new-model feasibility: TimesFM 3 loads the pinned weights, produces finite three-channel forecasts and quantiles at context 128/horizon 1, reproduces the same forecast to 1e-5, and has median per-batch latency below 5 seconds and peak allocated GPU memory below 20 GiB on the declared A10G. These deliberately generous operational gates do not imply anomaly-detection efficacy. A development-only step probe reports the same onset/retention metrics with this actual FM, without a required favorable outcome or tuning.

ADVANCE only to a new frozen development design when QH1/QH2 controls pass, original-FM and calibration execution accounting passes, the new model is operational, and data accessibility is verified. HOLD on failed source identity, causal-window controls, nonfinite results, incompatible original code, or resource failures. Partial CPU success cannot be promoted to an FM success. If the chosen NAB original-model run is pending, overall qualification is pending. Candidate efficacy and novelty remain unproved even after ADVANCE.

## Boundaries and procedure

The CPU pilot runs only reviewed numerical code and our harness. Downloaded scripts' installation directives and plotting are never executed. Historical source remains unchanged in an external cache. Any adaptations are expressed in our wrapper and hash-bound, with reasons recorded before relevant model execution. A source or compatibility correction creates an amendment; old receipts remain intact.

Root alone handles AWS. GPU run ceiling: one g5.xlarge shared with candidate009, at most two hours total host time, external stop, combined reserve $25. Run models sequentially, no paid inference API, no model training. Model/data downloads are public GETs. Cache weights and third-party code outside Git. Model load and inference time and peak memory are measured, not inferred from parameter count.

The later H1 efficacy proposal is at least +5 percentage points episode recall over the strongest development-selected deployable baseline, with a paired episode confidence interval excluding zero and no more than +1 false alarm/day, subject to an absolute alarm ceiling and recovery noninferiority margin still to be set before heldout access. Those choices cannot be made from Q1 HAI outcomes because none are computed. Cross-channel controls, provenance assumptions, legitimate-change interventions, contamination sensitivity, run-level replication and power must be designed before this hypothesis can be confirmatory.
