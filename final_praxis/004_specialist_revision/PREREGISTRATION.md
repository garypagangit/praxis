# Final Praxis004: specialist revision feasibility

Version1.0,12September2026. Commit before model requests. Root's earlier infrastructure protocol was committed before starting AWS. This is the complete scientific feasibility protocol; no model outputs for004 have yet been generated.

**RQ:** On real SWE-bench Verified issues, can a repair model preserve a correct initial patch under incorrect specialist feedback while recovering an incorrect patch under valid feedback? Does the public scaffold have enough capability and valid feedback to measure both transitions?

**Literature:** [ExecCritic](https://arxiv.org/html/2609.09133), sections3/7, separates Test and Repair and identifies co-adaptation of shared roles as a future concern. Its current [code](https://github.com/MSR-Orchard/execcritic) already supports KEEP_ORIGINAL. [When Helping Hurts](https://arxiv.org/html/2606.02866) already studies grounded critics and evidence gating. [SRU](https://arxiv.org/html/2608.26511v1) distinguishes harmful yielding from useful updating. This initial experiment is a scaffold/capability study, not a reproduction of trained ExecCritic models, a new rollback method, or evidence of internal neural skill corruption.

**Frozen public base:** `princeton-nlp/SWE-bench_Verified`, revision `c104f840cc67f8b6eec6f759ebc8b2693d585d4a`; ExecCritic source reference `1891f8efa473d1917c716cd4d80db1a6186721ad`; official evaluator `swebench==4.1.0`. Select the first four lexicographic instance IDs with `repo == sympy/sympy`, using no model outcome, gold-patch complexity or test-success information. Retain all four regardless of difficulty or infrastructure failure. Public data and source hashes are saved before inference. These test issues are never training data.

**H-Q:** Public source/images and the official evaluator yield auditable expected BASE-unresolved/GOLD-resolved controls. BASE receives only a comment in `sympy/__init__.py` to avoid the official evaluator skipping empty predictions; it changes no executable behavior. GOLD uses the withheld reference patch. These are benchmark-integrity controls, not model results. Evaluate in root-managed Docker with no network, host mounts or privileges, at most1worker,2CPUs,8GiB memory,512PIDs and900seconds per evaluation. Retain logs, prediction hashes and failures. Missing/unexpected controls are a technical qualification failure, not a scientific null.

**H1, capability:** at least one initial model patch is correct and one is incorrect. Otherwise both preservation and recovery cannot be evaluated in this tiny sample.

**H2, failure mechanism:** some intended-mistaken specialist feedback that passes the ordinary operational admission rule is semantically invalid against the withheld reference and causes correct-to-wrong revision. No observed example at n=4 is inconclusive.

**H3, candidate intervention:** issue-grounded evidence review reduces harmful revision while retaining useful recovery compared with plain revision and a generic verifier. This pilot provides case evidence only. The potential later contribution is counterfactual feedback training and prevention of role co-adaptation; an evidence-review prompt itself is not claimed novel.

**Runtime/evaluator separation:** models receive instance ID, repo, base commit, issue statement and deterministic lexical retrieval from public Base source. They never receive reference patches, official test patches, FAIL_TO_PASS/PASS_TO_PASS labels, Gold checkouts or reference-derived file hints. Store evaluator data separately; do not pass entire fixture rows through a prompt template.

**Model-stage protocol:** generate one immutable initial patch per issue/model before feedback. Independently generate issue-grounded and intentionally mistaken specialist probes using issue and Base context, without the initial patch or Gold. These are intended conditions, not verified labels. Assess Base execution for the normal admission rule; never select exposure using the later Gold validity audit. Missing or inadmissible probes remain visible. Repairer-visible feedback uses identical formatting and hides grounded/mistaken condition names.

Fork identical initial bytes into KEEP_ORIGINAL, NO_FEEDBACK_REVIEW, PLAIN_GROUNDED/MISTAKEN, GENERIC_GROUNDED/MISTAKEN and EVIDENCE_GROUNDED/MISTAKEN. Evidence review requires a KEEP/REVISE decision, an issue-backed behavior claim, an alternative explanation and a minimal edit. One revision maximum and independent contexts/checkouts. Invalid schema/patch output retains the initial patch and receives a protocol-failure label. Models must earn improvement over keep-original and equal-cost review.

Start with available Bedrock `qwen.qwen3-coder-next`; a separate registered model-family run may use `mistral.devstral-2-123b`. Do not pool them. Temperature0, at most4096output tokens, bounded public-source context, at most2transport attempts, stable content-validated IDs and a shared$25 inference ledger. AWS managed weights are not hash-pinned. All attempts/cost uncertainty remain recorded. Root supervises AWS execution, independent stop schedules and S3 checkpoints.

**Outcomes:** per-issue initial/final official resolution; correct-to-wrong and wrong-to-correct counts with their distinct denominators; all-task accuracy; intended and audited probe labels; KEEP frequency; schema/application/probe/infrastructure failures; tokens, latency and cost. Zero denominators are undefined. Correctness strata are determined only after execution and never route runtime decisions. Four issues do not support efficacy, non-inferiority or statistical safety claims.

**Advance/falsification:** do not interpret efficacy when initial correctness is at a floor/ceiling, probes are unavailable, labels leak, initial hashes differ or official verification is missing. Generic/no-feedback review matching the evidence policy means the proposed mechanism has not been established. Preservation due solely to KEEP must be evaluated against lost valid recovery. Any cohort expansion, training or outcome-informed policy change receives a new dated protocol before further model requests. A publishable study would need a specific method beyond these controls, more repositories and unseen specialists.
