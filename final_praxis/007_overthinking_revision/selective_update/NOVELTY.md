# 007 stage-two novelty decision — 12 September 2026

**Decision: reject a broad novelty claim; retain a narrowly scoped comparative experiment.** Counterfactual sycophancy mitigation, actual calls to a blinded counterpart, and preserving legitimate evidence updates already exist. Exhaustively swapping a separable peer assertion and using disagreement to veto revision is a concrete engineering difference from the methods inspected, but that alone is weak publication novelty. The strongest testable contribution is whether *interventional disagreement adds predictive and decision value beyond evidence-only checking and ordinary repeated-call disagreement at matched cost*. Treat stage two as a falsification study until this distinction succeeds. No paid calls or resources were used for this review.

## Precise candidate and its limits

Let h=(question, frozen initial answer y0), e be a separately provided evidence span, and a range over every allowed answer label. Construct independent contexts C(h,e,a) that differ only in an explicitly non-evidential assertion. Let C(h,e,empty) omit that assertion. Define y_e = f(C(h,e,empty)) and y_a = f(C(h,e,a)). A deterministic output-only gate is:

```
G(h,e) = 1[all outputs valid and nontruncated]
         * 1[y_e != y0]
         * product_over_all_labels_a 1[y_a == y_e]
y_out = y_e if G(h,e) == 1 else y0
```

This is our proposed process, not a result. The literal all-label set must include the initial label and the candidate label. Invalid/truncated replies reject the proposed update but are also reported separately so a broken generator cannot look like successful resistance. Preserve the same initial answer and evidence bytes in every intervention. Do not expose other counterfactual outputs to a branch being measured.

If genuine conditional label log-probabilities are available, one possible later continuous score is `m = min_a [log p(y_e|C(h,e,a)) - max_{b != y_e} log p(b|C(h,e,a))]`, with an evidence-only margin check. This is ordinary robust-margin construction, not a new theorem. Hosted verbal confidence is not a substitute for token probabilities. For hosted models without comparable logits, preregister the hard gate above and explicitly measured disagreement; do not retrofit probability language.

**An informative structural constraint:** this gate can only veto the evidence-only solver's answer. On items where y0 is wrong and y_e is correct it cannot improve recovery over that solver; it can only preserve or suppress it. On items where y0 is correct and y_e is wrong it may prevent damage. Its contribution therefore must be a better harm–recovery tradeoff or lower harmful accepted-update risk at matched update coverage, not an unconditional claim to improve every outcome. This deduction follows directly from the proposed rule.

**Required scope:** the changed assertion must be designated unsupported pressure, not trustworthy testimony. If a source's reported label is itself legitimate evidence, counterfactually replacing it changes the evidence and invariance is the wrong target. Keep provenance fixed and define separable fields prospectively. Evidence that explicitly contains the answer can make the test trivial; report this and separately test genuinely explanatory material. Do not rewrite rationale conclusions or benchmark keys after seeing model output. Entangled messages are a documented boundary unless separately annotated and frozen.

## Most defensible stage-two question

At a fixed call/token budget, does all-label interventional instability identify harmful proposed updates beyond (a) the independent evidence-only answer and its confidence and (b) ordinary repeated-call instability, while retaining a prespecified proportion of valid-evidence recoveries on untouched public test items?

This is stronger than showing that the gate beats unguarded pressure or always-KEEP. Those comparisons are easy to win by refusing to update. Suggested comparison set:

1. Original initial answer / always-KEEP; ordinary unguarded revision; one independent evidence-only solver.
2. Evidence-only solver plus ordinary evidence validation, and an initial/candidate confidence gate with calibration-only thresholds.
3. SWAY-style imagined counterfactual scaffold, explicitly labeled an adaptation of its published prompt.
4. Actual independent evidence-only repeated samples, both majority voting and unanimity-veto variants; allocate the same number of useful calls and the same per-call limits as the label audit. Report consumed tokens, not just nominal ceilings. Duplicate greedy calls are not a credible self-consistency baseline.
5. Proposed all-label gate, plus an ablation with only one alternate label to establish whether enumeration adds value.

Use the same frozen initial answers and candidate responses where a comparison permits it. Select operating thresholds on untouched calibration material only, then lock them before held-out inference. Report benchmark-key C-to-W, W-to-C, net accuracy, update coverage, harmful accepted-update risk, invalidity, and compute. Confidence bands resample questions, keeping conditions paired. Matched-coverage comparisons must not use test labels to tune thresholds. A conditional analysis asking whether label instability predicts errors after evidence-only confidence and ordinary disagreement is useful, but must have adequate sample size and be declared before fitting.

Include unsupported pressure, valid evidence, irrelevant evidence and internally invalid evidence as separately frozen strata if data and annotations support them. No-evidence pressure alone is insufficient: an evidence-only solver can remove that pressure without any label enumeration. Retain prior calibration exposure and problem/key validity audits from the 007 pilot; claims are benchmark-key correctness until independently audited.

## Falsifiers and investment gate

Reject the added mechanism if it fails to beat the stronger matched-cost evidence-only/repeated-sampling baseline at the prespecified recovery or coverage constraint; if gains come entirely from extra calls, format rejection, answer-bearing rationales or keeping every initial answer; or if performance disappears on held-out questions and a second model family. A useful numerical recovery-loss tolerance and minimum harm reduction must be frozen by the root protocol before outcomes, with enough initially correct and incorrect items to measure both. This memo does not select thresholds from pilot results.

If the exhaustive gate is equivalent in decisions to a cheaper evidence-only checker, adopt the cheaper checker and report a negative result. If source reliability makes the label legitimate evidence, reject the nuisance assumption for that stratum rather than count rational changes as failures. Invariant but consistently wrong answers also falsify any claim that invariance certifies correctness.

**Investment recommendation:** fund a bounded stage-two comparison; do not yet make this the primary long-term publishable-method investment. Novelty confidence is low-to-moderate for this narrow external veto and low for the broader idea. A convincing paper would need an empirical finding that the intervention-specific signal adds value, an explicit operating-domain analysis, and strong recovery-preserving comparisons. Absence of an exact title match in this search is not evidence of novelty.

## Follow-up: evidence interference and the root's bounded implementation

The root's proposed executable pilot uses 64 calibration and 128 untouched test questions, two models, and three evidence conditions: none, the item's published author explanation, and a deterministic rotated explanation from another item. That third condition is **mismatched author evidence**, not established contradictory or false evidence. Likewise, the original explanation is a published reference, not independently established clean evidence. An explanation about an unrelated claim is a relevance test. A reference plus an unrelated explanation is a distractor mixture unless someone verifies a substantive contradiction. Keep these names honest.

An additional close primary paper is [When Evidence Conflicts, Han et al., v1, 13 May 2026](https://arxiv.org/html/2605.14115v1). It evaluates correct-only, incorrect-only and both evidence orders on HealthContradict, and combines confidence with a trained risk detector for selective prediction. The detector uses uncertainty and question/document embeddings; its target is confidently wrong predictions, not purely an unsupervised contradiction detector. Thresholds transfer from training to test. [Author-linked source code](https://github.com/YikunHan42/When_Evidence_Conflicts) is public according to the paper; its implementation was not downloaded in this follow-up. This establishes that conflict-aware selection beating confidence-only is not a new contribution. Our remaining difference is the incremental value of controlled **peer-assertion** interventions over repeated evidence adjudication. Separately, [Trust, but Don't Verify, Pradhan & Goley](https://arxiv.org/html/2606.05403) shows that the presence of analytical-looking material can dominate actual numeric validity, reinforcing the need to test evidence quality rather than infer it from agreement.

Root's matched-call plan is sensible for a cheap falsification pilot: share evidence-only draw B0; compare B0 plus TRUE/FALSE-assertion draws against B0 plus two additional independent evidence-only draws, using both majority and unanimity/KEEP controls. With all checks at temperature 0.3, one realization under each label is **a finite sampled label audit**. The aggregation rule is deterministic given the outputs, but the observations are stochastic. A single item's disagreement does not isolate the causal label effect from generation variance. The paired policy-level contrast against independent repeated draws is the appropriate test. Do not advertise a certified response envelope, worst-case probability bound, or per-item invariance guarantee.

The two zero-shot SWAY-inspired branches are useful diagnostics, but they omit the paper's ten fixed demonstrations. Explicitly call this an adaptation; a positive result against them does not establish superiority over published SWAY. A follow-up publication comparison should include the full scaffold and account for its token overhead. Removing only the peer label while retaining the identical initial answer is a precisely defined control, not complete context blinding; the initial reasoning can still anchor every checker.

Before freezing, record the donor pairing algorithm within split, all evidence bytes, exact independent sampling/request identities, invalid-output behavior, and calibration-only coverage matching. Independently inspect a fixed sample of donor pairs for accidental relevance, duplication and answer-bearing text. Do not exclude difficult pairs based on model answers. Keep the 64-token initial prompt expressly short-answer; still report truncation and formatting so KEEP cannot hide an invalid-check floor. Identical initial answers and common B0 responses should remain shared across policies, with all dependence preserved in question-level uncertainty estimates.

**Advice remains: run the bounded pilot.** The current finite label audit adds no factual information, so it may lose to spending the same calls on independent evidence verification. Evidence acquisition is a more meaningful alternative when truly conflicting sources cannot be resolved from the supplied text, but it introduces retrieval/provenance and unequal-information comparisons. Do not add it to this pilot opportunistically. If the label audit shows no incremental value, prefer the cheaper successful verifier or design a separate evidence-acquisition study; do not rename an ordinary consistency effect as a new mechanism.
