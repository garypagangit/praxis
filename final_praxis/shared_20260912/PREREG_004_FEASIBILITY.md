# Final Praxis004: pre-compute qualification protocol

Frozen12September2026 before any model requests, AWS instance start or experimental processing for this campaign. The public literature, source metadata and AWS read-only resource/pricing inventory have been inspected. This protocol authorizes the infrastructure/capability feasibility stage. The full study protocol and exact source/data manifest must additionally be committed before model calls; any later change is versioned before outcomes are examined.

**Research question.** On public SWE-bench Verified repair tasks, can a testing specialist's incorrect but executable feedback cause a repair model to damage an initially correct solution, and can issue-grounded review reduce that harm while allowing useful corrections?

**Literature basis.** [ExecCritic](https://arxiv.org/html/2609.09133) demonstrates Test/Repair interaction and explicitly identifies co-adaptation between shared roles as a future concern. Its current [public scaffold](https://github.com/MSR-Orchard/execcritic) already allows retaining the original patch. [Sycophancy Suppression Can Impair Rational Updating](https://arxiv.org/html/2608.26511v1) establishes that suppressing yielding can impair valid updating. [When Helping Hurts](https://arxiv.org/html/2606.02866) makes an execution-grounded critic or evidence gate alone insufficient novelty. These sources motivate measuring harmful revision and useful recovery separately; none establishes that our proposed modification works.

**H1.** At least some naturally generated or controlled mistaken specialist tests will execute and meet the base-failure admission rule while disagreeing with the task's withheld reference behavior. Their feedback may induce correct-to-wrong revisions. The corresponding null is no admitted misleading feedback or no harmful revision in this feasibility set. Failure to observe a rare event in four tasks is not proof of absence.

**H2.** A process that explicitly compares specialist claims against the original issue and permits retaining the initial patch will reduce harmful revision without eliminating valid recovery, relative to ordinary revision. This is a candidate behavioral mechanism, not a claim that the review prompt is a novel defense. Matched-feedback training and role co-adaptation controls are subsequent stages only if the effect and evaluation are feasible.

**Technical prerequisite hypothesis.** The official public issue/repository artifacts can be materialized and scored in isolated AWS containers under the frozen task protocol, with reference-patch positive controls and unmodified-base controls separating implementation failure from a scientific null.

**Sample and inference scope.** Use four deterministically selected SymPy issues from the public Verified release, selected by lexicographic instance ID within the repository, without inspecting model success or reference-patch complexity. Source IDs and hashes are frozen before inference. This is a single-repository feasibility sample, not a representative or powered benchmark. No trained-paper headline score is claimed from available untrained scaffold models. Parent model calls use the bounded AWS Bedrock Qwen3CoderNext and Devstral2 adapters; inference metadata, prompts, outputs, costs and model IDs are retained. Managed weights are not represented as pinned open checkpoints.

**Conditions.** Freeze each initial model patch before any feedback. Preserve that patch across no-feedback/keep-original, ordinary specialist-feedback revision, a generic verification control and issue-grounded review. Include intended-useful and intended-mistaken tests; labels describe the generator condition, not assumed validity. Models receive only issue/source context and admissible execution feedback, never reference patches, official correctness labels or hidden initial correctness. The evaluator can audit a test against reference behavior after generation, but that audit must not select the feedback exposed to the model. Conditions requiring inadmissible/missing tests are recorded as unavailable, not silently replaced.

**Outcomes and failures.** Report all four correctness transitions, admission/validity counts, patch-application failures, runtime failures and actual token/time cost. No-feedback is the baseline. Official withheld tests operationalize correctness; they do not prove every possible semantic property. Four tasks cannot support a tight correction non-inferiority bound. An infrastructure failure, a floor of zero initially correct patches, or no useful correction opportunities makes this screen inconclusive and triggers a specified development amendment, not a positive or negative thesis claim.

**Compute and isolation.** Start the existing stopped004 host only after committing this file. Its AWS Pricing API rate is$1.006/hour; install an AWS-side eight-hour stop schedule before boot and a guest shutdown timer after SSM becomes available. Initial inference ledger$25; conservative per-job envelope$75 including compute/storage overhead. Model-generated code runs in restricted containers without cloud credentials or network access. Original experiments and datasets remain intact. No model invocation or training is part of the host inventory probe.

**Investment decision.** Proceed to a larger preregistered development sample only if public artifact evaluation works and the observed conditions contain both preservation and correction opportunities. A main Praxis contribution would need a new method beyond existing keep-original/generic-verifier baselines, with multiple specialists and held-out repositories. No publication guarantee is made by this feasibility protocol.
