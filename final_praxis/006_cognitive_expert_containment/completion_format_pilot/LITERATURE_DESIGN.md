# MiCRo completion follow-up: literature and prospective design

13 September 2026. Read-only review; no inference or cloud mutations. Recommendation: run one bounded, preregistered 32-question chat-format pilot, then stop this implementation if it fails. Do not retroactively pass the completed raw-prompt study or begin a containment efficacy study yet.

## What the completed experiment supports

The independently audited float32 run completed all 816 assigned generations. Intact flexible exact match was 80/256 (31.25%); logic ablation 13/256 (5.08%); social ablation 91/256 (35.55%). Removing logic lost 26.17 percentage points, with a paired 95% interval20.31?32.03. All technical and integrity checks passed. The only failed registered gate was intact truncation: 48/256 (18.75%), above 10%. Its final decision remains **DO_NOT_ADVANCE_CURRENT_QUALIFICATION**.

This is evidence of useful logic contribution under the declared parser, despite failure of the complete qualification. Only 2 of the 80 intact correct answers were truncated; 78 correct answers ended normally. The jointly nontruncated intact?logic difference was 30.77 points over 143 pairs, supporting investigation but not replacing the primary estimate because completion determines subset membership. Strict exact match was 2/256, with only 8 strict extractions: a literal phrase requirement is different from semantic answer correctness. These figures do not establish that the other 78 flexible successes are invalid, nor that every extracted answer is a completed solution. Source: existing FP32 completed/AUDIT.json and RESULTS.md, with hashes in REVIEW_INPUTS.json.

The coordinator also reports an exploratory repetition diagnostic: 37/48 capped intact outputs have at least 0.9 tail periodicity at some lag from 1?64 tokens. This was measured after outcomes and is not a registered gate or proof of cause. It supports checking the source-backed format before considering any longer budget.

## Primary-source rationale

The [official pinned generation helper](https://github.com/BKHMSI/mixture-of-cognitive-reasoners/blob/275a5e4b1369ff19c8e3f33f42f16bc5ef19e6d7/generate.py) wraps input as a user message and directly calls `apply_chat_template` with an assistant generation prompt. Its helper defaults to 1,024 output tokens; the CLI passes 512. Neither demonstrates the published benchmark cap. This supports checking the chat convention while retaining our fixed budget; it does not justify copying undocumented paper settings or choosing a larger budget after outcomes.

The training source constructs user/assistant message pairs in [train_datasets.py](https://github.com/BKHMSI/mixture-of-cognitive-reasoners/blob/275a5e4b1369ff19c8e3f33f42f16bc5ef19e6d7/data_utils/train_datasets.py); [train_sft.py](https://github.com/BKHMSI/mixture-of-cognitive-reasoners/blob/275a5e4b1369ff19c8e3f33f42f16bc5ef19e6d7/train_sft.py) sends these datasets through SFTTrainer; the [completion collator](https://github.com/BKHMSI/mixture-of-cognitive-reasoners/blob/275a5e4b1369ff19c8e3f33f42f16bc5ef19e6d7/data_utils/data_collator.py) recognizes the Llama assistant header and masks preceding labels. This is consistent with a chat-trained model; the source alone does not prove the exact history of the released checkpoint.

The [pinned harness task](https://github.com/EleutherAI/lm-evaluation-harness/blob/ad8737ae7fad24cf64e50fc7fc31397bff586b9e/lm_eval/tasks/gsm8k/gsm8k-cot-zeroshot.yaml) supplies raw Q/A text and strict/flexible extraction. That YAML does not determine whether a model wrapper applies chat formatting. The [MiCRo paper v3](https://arxiv.org/html/2506.13331v3) already reports useful logic ablations and 34.7% GSM8K accuracy for this backbone, but leaves some invocation details unstated. This follow-up qualifies an operating protocol; it supplies neither exact reproduction nor method novelty.

## Freeze one candidate before further compute

RQ1: Does the fixed chat convention yield sufficiently complete, useful intact responses within 1,024 tokens? RQ2: If so, does logic removal still materially reduce capability on fresh held-out questions?

Use the same pinned checkpoint, tokenizer, source, float32 loader, TF32-off settings, and numerical gates. Fix the sole candidate now: a single user message containing exactly `Q: {question}\nA: Let's think step by step.`, rendered through the pinned tokenizer's chat template with `add_generation_prompt=True`, no tools, no custom system instruction, and `date_string="13 Sep 2026"`. The template supplies its own default system header/date and BOS; do not add a second BOS. Keep the original greedy decoding, both EOS IDs, stop strings, and 1,024-token cap. Save rendered prompts/token identities. This tests the complete tokenizer chat wrapper, including its default system text, rather than only role-token insertion.

Stage 1: freeze 32 previously unused GSM8K TRAIN questions and generate intact raw/chat responses on every question (64 total), with fixed alternating order. The raw arm is diagnostic, never an alternative selected if chat fails. Require all technical checks, chat truncation at most 3/32, digit-containing flexible extraction at least 29/32, and **nontruncated flexible correctness at least 8/32**. This last guard prevents completed numeric nonsense advancing. Report raw/chat paired truncation, completed correctness, token counts and stop reasons. Do not tune wording, dates, cap, model or thresholds from these outcomes. These are cheap feasibility thresholds; 3/32 truncations has a Wilson 95% upper bound around 24%, not proof of a population rate below 10%.

Possible next study, NOT part of this pilot: a pass permits separately preregistering a fresh 256-question TEST cohort with the fixed chat format under intact, logic-ablation and social-ablation conditions (768 total). Freeze that future protocol and data before any of its inference; the pilot does not automatically start it. Keep the previous full-cohort flexible scoring, 25% intact accuracy, 10% intact-truncation limit, 90% extraction, 10-point paired logic-loss threshold and positive 95% lower bound, with all technical/integrity gates. Also report nontruncated-correct counts and strict extraction; neither silently replaces the primary parser. Bootstrap paired IDs 10,000 times with a fixed declared seed. Retain every assigned question. A pass permits designing a new fault-containment experiment; it does not validate one.

## Public data and stopping decision

Use original [GSM8K](https://github.com/openai/grade-school-math/tree/3101c7d5072418e28b9008a6636bde82a006892c), whose [README](https://github.com/openai/grade-school-math/blob/3101c7d5072418e28b9008a6636bde82a006892c/README.md) documents public question/solution files and final numeric labels. The repository includes an [MIT license](https://github.com/openai/grade-school-math/blob/3101c7d5072418e28b9008a6636bde82a006892c/LICENSE). Preserve split/source indices and hashes; use outcome-independent hash ordering. Exclude all prior campaign test identities, including the completed 256 and earlier 40, plus normalized overlaps with training. Exclude the prior 16 pilot and any other previously processed training diagnostics from Stage 1. ?Fresh? means unused in this campaign, not absent from model training.

This pilot plans exactly 64 generations, with an explicit per-job cost/runtime cap and automatic publication of its final positive, negative, or incomplete review. A pilot failure prevents proceeding to a full test study. If it fails, close this implementation and do not extend the cap or search more prompts automatically. The broader specialist-corruption idea still needs a demonstrably useful baseline and a new mechanism that beats permanent ablation and random controls across faults.
