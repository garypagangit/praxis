## Evidence and literature basis

The previous FP32 qualification, `fp006-logic-ec92d2561c`, completed 816 cells with all numerical/integrity checks passing. On its 256 test questions, intact flexible correctness was 80, logic-ablation correctness 13, and social-ablation correctness 91. The intact-minus-logic difference was 26.17 percentage points, paired 95% interval [20.31,32.03]. Its formal decision remains DO_NOT_ADVANCE_CURRENT_QUALIFICATION: 48/256 intact responses hit the 1,024-token cap, above its 10% limit. Only two intact flexible-correct responses were capped. An explicitly posthoc, outcome-blind token-repetition diagnostic found strong periodic tails in 37 of those 48 capped responses. This supports investigating serialization, without treating a longer cap as a demonstrated remedy or replacing any prior endpoint.

The [MiCRo paper v3](https://arxiv.org/html/2506.13331v3) already studies expert ablation and steering. Its [pinned generation helper](https://github.com/BKHMSI/mixture-of-cognitive-reasoners/blob/275a5e4b1369ff19c8e3f33f42f16bc5ef19e6d7/generate.py) uses a user message and `apply_chat_template(..., add_generation_prompt=True)`. The pinned training datasets contain role-tagged messages; the completion collator masks up to the assistant header. The [pinned harness task](https://github.com/EleutherAI/lm-evaluation-harness/blob/ad8737ae7fad24cf64e50fc7fc31397bff586b9e/lm_eval/tasks/gsm8k/gsm8k-cot-zeroshot.yaml) supplies the raw Q/A task and numeric extraction, but does not itself settle model-wrapper chat formatting. These sources motivate one fixed serialization check. LITERATURE_DESIGN.md supplies source links and interpretation limits. The exact published benchmark invocation remains incompletely documented.

RQ: Does the author's chat-template convention produce sufficiently complete and useful intact GSM8K responses within the unchanged generation budget to justify a fresh held-out qualification?

H1, directional diagnostic: With identical task content, the chat wrapper reduces capped-response frequency relative to raw input. Report paired completion changes and completed correctness; this small pilot is not powered as an efficacy claim, and a positive raw-versus-chat difference is not an additional gate.

H2, feasibility gate: The sole candidate chat format yields at most 3 capped responses, at least 29 digit-containing flexible extractions, and at least 8 nontruncated flexible-correct responses among the fixed 32 questions, with complete data and all technical checks passing. These thresholds are our prospective decision rules, not literature results. Passing a 32-item screen does not establish a population truncation rate below 10%.

## Fixed sample and interventions

Use original public [GSM8K](https://github.com/openai/grade-school-math/tree/3101c7d5072418e28b9008a6636bde82a006892c). data_receipt.json fixes source URLs, byte hashes and original indices. Exclude the previous 16 train pilot questions, every normalized question in the test split, and duplicate normalized train questions. Normalize with NFKC, casefold and collapsed whitespace. Sort eligible train questions by SHA256 of `completion-format-v1:train:<exact question>`, breaking ties by source index; take the first 32. This leaves 7,457 eligible train questions. Selection does not use model correctness. "Unused" means unused in this campaign, not absent from checkpoint training.

Every selected question receives exactly two intact generations: raw and chat. Alternate arm order by fixed row position, with raw then chat on the first row. There are exactly 64 model responses and zero held-out test responses. Reset expert ablation to the empty list for every generation and start each with an empty KV cache. No routing modification, model adaptation, fault injection, answer repair, custom system instruction or new task instruction is introduced.

The raw task is exactly `Q: {question}\nA: Let's think step by step.` with BOS added once. The chat condition puts that exact same text in one user message and applies the pinned tokenizer template with `add_generation_prompt=True` and fixed `date_string="13 Sep 2026"`. The tokenizer supplies its default system metadata and assistant header. Encode the rendered chat with `add_special_tokens=False` so BOS appears exactly once. This compares the complete wrapper including default system metadata, not an isolated role-token effect. Save every rendered prompt and input token ID in data.json; the cloud tokenizer must reproduce every frozen input before inference.

## Model, numerical checks and generation

Reuse the exact checkpoint, source, tokenizer, FP32 loader, source patch, architecture/hash checks, strict tensor loading, and TF32-off settings documented in SOURCE_CONTRACT.md and loader_settings.json. The inherited loader's architecture/source contract applies; protocol.json here overrides predecessor evaluation settings. No weights or tokenizer files are published to Git.

Numerical checks use the two original short probes plus their fixed chat-wrapped counterparts. Check each under intact, logic ablation and social ablation, for twelve diagnostic records. Require all previous ten technical categories, including identical cache/full and eager/SDPA next tokens and maximum absolute differences at most 0.001. Ablations in numerical probes are loading/routing checks only; both study arms remain intact. A failure stops before pilot inference and cannot be waived. This does not establish universal numerical equivalence.

Greedy batch-one decoding uses FP32 SDPA, seed 20260913, 1,024 new tokens maximum, EOS IDs 128001/128009, pad ID 128004, and original stop strings `Q:`, `</s>`, `<|im_end|>`. Save raw/cleaned responses, generated token IDs, stop reasons, timing and prefill/decode route counts. Require finite logits, exact input hashes, and route totals equal to 16 times processed token count. A token-cap ending remains a capped response, even if a numeric answer appears earlier. No repetition penalty, early answer-based stop or length extension is introduced.

## Scoring, automatic review and stopping

Preserve the pinned harness's flexible-last-number and strict-first-phrase regex/exact-match normalization, including numeric-format quirks. Flexible correctness among nontruncated chat responses is the feasibility endpoint; its count uses all 32 assigned questions as denominator. Also report full-cohort flexible/strict accuracy, digit extraction, stop reasons, tokens, and raw/chat paired changes. Truncated responses are retained; they cannot count toward the eight completed-correct gate. No semantic judge or human review is required.

The independent audit verifies the exact protocol/data hashes, all 64 unique cell identities, question/prompt/token/response hashes, generation metadata, route counts, and numerical evidence, and recomputes scores from saved responses. Partial, corrupt, nonfinite or technically invalid runs cannot pass. Parser and gate tests cover boundary, failure and integrity cases. Raw performance is descriptive and cannot become the chosen candidate if chat fails.

All gates must pass to return QUALIFIED_FOR_FRESH_TEST_REGISTRATION. This permits a separate prospective study on fresh excluded test data using the same fixed chat format; it does not start that study automatically, establish a useful-specialist test result, validate novelty, or select a primary Praxis. If any gate fails, return DO_NOT_ADVANCE_CURRENT_QUALIFICATION, close this fixed implementation, and do not automatically search additional prompts, models or token caps. No result from the previous qualification is overwritten.
