# Final Praxis 002 — Novelty Gate

Date: 2026-09-08
Decision: **PASS WITH NARROW CLAIM / proceed to preregistration**

## Candidate

**Deterministic Trust-Boundary Containment for Multi-Agent Security Workflows**

## Closest-work pressure test

The crowded neighboring literature already covers:

1. **AgentDojo** — realistic tool-using agent tasks under prompt-injection attacks and defenses. This establishes strong agent-security benchmarking; it is not evidence that deterministic handoff checks are novel by themselves.
2. **CaMeL / capability-style defenses and related least-privilege designs** — separate control/data or restrict capabilities to prevent unsafe tool effects. These weaken any architecture-only claim.
3. **Policy/enforcement frameworks for agentic systems** — deterministic policy checks, taint/provenance concepts, constrained tool execution, and defense-in-depth are established concepts.
4. **Multi-agent SOC prototypes** — detection/investigation/response agent chains already exist; a three-agent SOC architecture is not a contribution.

## Surviving novelty sentence

> Prior agent-security work evaluates attacks/defenses, policy enforcement, or task success, but Final Praxis 002 preregisters **cross-stage error propagation as the primary measured object**: whether a controlled invalid upstream handoff survives successive probabilistic agents and becomes an invalid downstream environmental action, and how deterministic gate placement changes propagation depth, escape rate, and clean workflow utility.

This is narrower than claiming a new secure architecture.

## What must be measured for novelty to survive

- exact stage where an invalid condition first appears;
- whether each downstream stage preserves, corrects, amplifies, or transforms it;
- whether a deterministic boundary contains it;
- final invalid-action execution;
- propagation depth and gate-placement effects;
- matched clean-workflow utility.

A simple attack-success-rate table is insufficient.

## Kill conditions

Kill or demote if the final protocol cannot attribute propagation stage-by-stage, if deterministic gates reduce only final tool execution without measuring cascade dynamics, if a final-action-only gate performs equivalently and makes handoff-gate claims unnecessary, or if literature review before submission finds a directly comparable stage-by-stage cascade-containment experiment.

## Gate decision

**Proceed.** The architecture is crowded, but the proposed primary construct—stage-attributed cascade propagation/containment under matched deterministic gate placements—remains sufficiently differentiated to justify a falsifiable experiment. Publication language must remain about the measured construct, not about inventing trust boundaries.
