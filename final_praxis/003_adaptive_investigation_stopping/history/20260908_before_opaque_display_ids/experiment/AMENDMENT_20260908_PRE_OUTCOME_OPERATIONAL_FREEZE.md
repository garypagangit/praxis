# Prospective operational completion amendment

Date: 2026-09-08. Timing: before any Final Praxis 003 non-fixture model execution or outcome inspection. This file preserves the original README and methods document as evidence.

The earlier conditional methods gate permitted build but left model, corpus, review endpoint utility, interval implementation and exact runtime unspecified. Preregistration v1 now fills those details with a generated inert corpus expressly allowed by the methods document, one immutable model revision, no optional uncalibrated A3, and a conservative abstention utility rule. No existing numerical promotion, kill, harm or review threshold changes.

The builder read only the existing Final Praxis 003 conceptual policy and threshold definitions for policy selection. No historical PX-057 per-case outcome table was used to select or tune these policies. Prior-session general awareness that old work existed does not constitute an independent historical audit; the concrete independence basis is mechanical adoption of the already written A0/A1/A2/A4 definitions without outcome optimization. The new corpus, evidence schedules and metadata are generated before any new outcomes.

Novelty review now includes REFRAIN, MiCP, SIR-Bench and NVIDIA's security-workflow stability stopping. Only the bounded paired evaluation with explicit review/harm/prevention denominators proceeds. No new algorithm or first security-stopping claim is authorized.

The review gate starts at earliest eligible stopping round 2; round 1 is always CONTINUE. REVIEW means mechanically continue, with unresolved final-round review mapped to abstain and zero utility. Any case with REVIEW counts against the unchanged 20% review ceiling. This can make A4 worse than A1, which must be reported without post-outcome rescue.

Runbook Phase 4 is satisfied by two disjoint, prospectively generated infrastructure pilot cases, each with eight real model rounds. They test artifact completeness and independent verification, not scientific success. They cannot enter the 400-case discovery denominator or influence the already frozen discovery corpus/policy/prompt. This pilot provision is written before either pilot or discovery model output exists.

Token saving is measured from actual prompt and completion token counts through policy endpoints; both token and round saving must pass the original 20% threshold. Bootstrap comparisons against both A0 and A1 use one-sided 97.5% bounds to conservatively preserve the strongest non-adaptive comparison. All 400 cases remain in utility, harm and review denominators. Eight families share an authorization construct, so real-world scope is narrow and sampling CIs do not remove template dependence.
