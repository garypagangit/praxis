bounded code-study protocol. This is an engineering and methods judgment before
model-result inspection. It does not establish qualification success, a positive

Independent controls initially reproduced two recommendation defects: expected
missing assignments could still satisfy the model recommendation gate, and equal

and invalid observations still retain their registered operational denominators.

Exact paired tests retain four prospectively specified hypotheses and separate
reviewers. Bootstrap resampling uses source problems, jointly preserving native

uncertainty is calculated. Repeated calls and multiple proposals do not become
independent problems. Generated intents and prior experiments are not pooled.

## Interpretation boundaries that remain binding

The all-assigned H1 is the effect of the complete witness-selection policy,
including failure to find two passing witnesses. The feasible-only sensitivity
describes selection with equal displayed counts. Neither should be mislabeled
as the other.

A hard veto given a sound, authenticated failing test is logical enforcement.
Its existence alone is not an empirical defense contribution. A policy claim
requires the frozen equal-budget contrasts and useful-repair criterion; these
static edit heuristics are not state-of-the-art coverage/differential baselines.
An all-zero useful paired contrast cannot prove population noninferiority.

The test suite supplies finite executable outcomes, not proof of semantic
correctness. Public benchmark/pretraining exposure is unresolved. The code-study
actor is limited to semantic defects; the AST filter and credential/network
isolation are not a proof against arbitrary malicious harness attacks or a claim
that evaluator-process gold data is cryptographically isolated.

Freeze readiness permits the registered next step only after qualification and
technical gates pass. Final paper-development readiness requires completed
assignment accounting, immutable artifacts, outcome review and a claims table
matched to the observed evidence. Prior 004–008/FalseCite findings remain separate
historical evidence, as documented in paper_package/PRIOR_EXPERIMENT_APPENDIX.md.

## Final orchestration and closeout addendum

The subsequently reviewed run_study.sh completes development proposal execution
and both development review cohorts before the heldout phase. Heldout Qwen
proposal calls require both of its development review gates; stopped calls retain
proposal placeholders. Reviewer calls retain their corresponding model/cohort
gate. An EXIT handler writes phase, exit status, aggregate availability and durable
receipt counts, making an interrupted phase visible without claiming completion.
This is a best-effort process handler, not protection from host loss or SIGKILL.
Shell syntax verification is delegated to the Linux coordinator.

The reviewer was authorized to implement finalizer hardening. Its 19 self-authored
synthetic controls passed; these are implementation verification, separately
identified from independent analysis review. One control exercises the full
9,456-job closeout flow while replacing costly statistics and row serialization
with stubs. No real study outcomes enter these controls.

Finalization derives the exact frozen assignment universe: 5,516 native reviews,
3,940 generated reviews, 328 generated proposals, 656 total proposal directions
and 131,200 offline assignments. Per-problem splits, directions, reviewers, arms,
and the 33 repeated problem IDs must match, so merely matching global counts is
insufficient. Decision and proposal records must bind their exact assigned jobs;
duplicate IDs, changed hashes and changed identities fail validation. Missing
decision records remain explicit and cannot be counted as complete.

Technical gate counts are recomputed from captured records. The proposer gate
must agree with both development reviewer gates. The API ledger must use the
frozen $30 limit, permitted models, finite nonnegative amounts and valid usage
counts; unresolved reserved attempts remain charged. All gates, job/result files,
proposal manifests, the budget, reference manifest and model-source manifest are
hashed from the exact bytes parsed. Output accounting and completed eligible
model calls are reported separately. These controls preserve interrupted or
negative evidence; they do not turn a complete run into a positive method result.
