# Dataset evaluation: human, autonomous AI and conventional automated attacks

**Assessment date:** October 19, 2026. **Target:** the three RQs in [the research design](PRAXIS_RESEARCH_DESIGN.md). [Delivery tracker](PRAXIS_STATUS_TRACKER.md) · [Literature](PRAXIS_LITERATURE.md).

**Decision: reuse existing datasets for development and external probes; retain a new matched collection for the current thesis.** None of the sources reviewed here has been qualified as a complete replacement supplying verified human and autonomous-AI arms, conventional automation controls, matched multi-host target-side host/network telemetry, and adequate independent groups for the proposed transfer tests. This is a fit assessment of the reviewed sources, not proof that no suitable dataset exists anywhere.

“AI attack dataset” is ambiguous. Data used to train an AI intrusion detector need not contain attacks performed by AI. Scripted attack automation is not an autonomous LLM agent. AI-assisted human activity is a third condition, not automatically a human-only or autonomous-AI label. A benchmark environment or paper is also not necessarily a downloadable telemetry dataset.

## What a replacement dataset must contain

| Requirement | Why it is needed |
| --- | --- |
| Verified operator labels | Human, autonomous AI, conventional scripted automation and benign activity must be distinguishable from collection provenance, not guessed from command style |
| Matched conditions | Comparable objectives, tools, privileges, time windows, knowledge and recording pipelines across arms |
| Target-side telemetry | Synchronized host and network records that a defender could observe; agent prompts/reasoning are not substitute sensor evidence |
| Independent trial/group identifiers | Trial/reset IDs, human operator IDs and AI model/scaffold/configuration IDs support leakage-safe splits and RQ2 |
| Sufficient held-out groups | Repeated events/windows cannot substitute for independent humans, configurations or scenarios |
| Data quality and access | Usable files, terms of reuse, provenance, timestamps, missingness, exclusions and integrity checks |

**Verdicts:** **Supplement** = useful for a bounded part of the study. **Candidate—verify** = potentially valuable, but access or comparability is unresolved. **Different task** = useful cybersecurity data but its labels do not answer operator attribution. **Replacement** would require passing all requirements above; no row currently earns that verdict.

**Verification scope:** current primary release pages, original repository documentation and papers were inspected. Most large raw corpora were not downloaded or re-audited in this review. Access marked “public listing” means an advertised release/file inventory, not a successful full download or license audit. Counts are publisher-reported unless explicitly described otherwise. Unknown means not established, not necessarily absent.

## Why combining existing datasets does not solve the design by itself

Suppose GAMBiT or KYPO supplies every human example and Honey or COCHISE supplies every AI example. The class label then also identifies the source dataset. A model could exploit task vocabulary, shell banners, operating systems, collection timestamps, logging format, tools, censoring or response-latency measurement. Strong accuracy would not establish transferable autonomous behavior.

Removing obvious source IDs helps, but cannot prove that latent source differences are gone. Grouped splits within each source still leave source/class confounding. Such pooled experiments should be labeled exploratory cross-source classification. A credible external probe needs mapped common features, documented mismatches and source/condition controls; it cannot silently become the main matched-trial evidence.

## Collection decision and minimum new evidence

| Missing or unqualified evidence | New collection must provide | Existing material to reuse |
| --- | --- | --- |
| Comparable operator classes | Human, autonomous AI, non-AI scripted control and benign runs under the same recording pipeline | D03 suggests explicit automation-level comparison; D12 informs scripted-control design |
| Same environment and objectives | Matched GOAD scenarios, privileges, tools, knowledge conditions, access windows and counterbalanced order | D02 can inform agent/harness preparation; deploying it still generates new data |
| Defender-visible evidence | Native host logs and synchronized network capture for every arm, plus coverage/loss audit | D11/D15 inform joins and sensor validation; D13/D14 inform provenance processing |
| Reliable origin and grouping | Verified autonomy/interventions, reset IDs, human identities kept privately, model/scaffold versions and trial boundaries | D01 configuration variation and D09 participant grouping inform schema design |
| Generalization evidence for RQ2 | Independent held-out human operators and AI configurations/families, with exact claim scope | D04 motivates scaffold/family transfer checks; existing AI-only records are supplemental |
| Defensible model comparison for RQ3 | Same observations/features/folds for all candidates, fit-only preprocessing, independent sample/precision rationale | Existing corpora support code smoke tests and preliminary learning curves, not proof of adequate new-trial sample size |

**Recommended action:** proceed with the matched collection while first qualifying D07, D03 and D08 for a narrower human/AI comparison opportunity. If one supplies all required raw evidence and metadata, reconsider new collection rather than dismissing it. If the project instead changes its thesis to command-trajectory attribution, AI-family fingerprinting or CTF assistance outcomes, existing sources may support that narrower study. That would require an explicit RQ/scope revision.

Fresh data alone is not enough: a single human, one AI configuration, mismatched tools or inadequate independent trials would recreate the same limitations. The October 21 feasibility decision and October 26 freeze in the tracker must establish attainable group coverage and precision before scored runs.
