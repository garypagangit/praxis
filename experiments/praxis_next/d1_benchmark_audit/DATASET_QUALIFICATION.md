# D1 dataset qualification: what each dataset can actually test

**Checked September 23, 2026. No models fitted, large files downloaded, or AWS workers started.** This review reread the existing CSV bytes, recalculated source hashes and stage counts, inspected the adapters, and checked primary release sources. [QUALIFICATION.json](QUALIFICATION.json) records file paths, hashes, schemas, native counts, source/date support and the eligibility decisions.

## Decision

**None of the four datasets currently supports an unchanged port of PX-082.** They can still contribute different, explicitly scoped measurements:

| Dataset | Available measurements | Qualified scope now | Temporal / campaign limit |
|---|---|---|---|
| SCVIC-APT-2021 | Author-attributed training CSV; 259,120 rows; six native labels including normal traffic | **Random development / exact-duplicate grouping** | Mixed timestamp precision, 220 anomalous 1970 rows, no qualified execution IDs, author test not acquired |
| DAPT2020 | Ten CSVs; 86,691 flows; five native labels including benign; five capture dates | **Conditional temporal measurement** and collection-group diagnostics | Flow start times exist, but stage/day confounding, completion-time qualification and rare-stage support prevent automatic all-stage temporal certification |
| DSRL-APT-2023 | Pinned author CSV; 65,000 rows; five native stage labels including benign | **Random derivative-data screening** | Generated attack timestamps do not establish a real sequence; dependent on DAPT2020; no campaign/generator IDs |
| S-DAPT-2026 | Primary manuscript records and prior intake plan; no acquired data | **Blocked for fitting** | Withdrawn arXiv manuscript; corrected data/generator release, actual clocks, groups and data rights unqualified |

The word **group** must name its unit. Grouping duplicate predictor rows is useful for controlling duplicate contamination; it does not create an independent incident. Public/private sensors and capture days likewise do not create independent APT campaigns. No independent repeated-campaign IDs were qualified for any of the four sources.

## 2. DAPT2020

**Actual inputs:** ten files under `C:/Users/garyp/OneDrive/Documents/codex/data/raw/dapt2020`. File names and SHA-256 hashes are in the JSON. Native targets are `Activity` and `Stage`; use `Stage` as the stage target and exclude `Activity` from predictors. The [author CSV documentation](https://gitlab.com/asu22/dapt2020/-/raw/main/csv/README.md) identifies the 85 columns and defines `Timestamp` as flow start. The [author collection description](https://gitlab.com/asu22/dapt2020/-/raw/main/README.md) describes a five-day public/private-network progression. Those are collection units, not verified repetitions of independent campaigns.

| Native stage | Rows | Actual support by date |
|---|---:|---|
| Benign, after spelling normalization | 63,712 | July 15–19, 2019 |
| Reconnaissance | 11,909 | July 16–17 |
| Establish Foothold | 8,604 | July 17 and 19 |
| Lateral Movement | 2,451 | July 18 only |

All source timestamps parse with `%d/%m/%Y %I:%M:%S %p`, spanning July 15, 13:45:37 through July 19, 22:29:23. Flow start is not full-flow availability. Before asserting `training_end < test_start`, qualify duration units, timezone assumptions, endpoint availability, and tied/overlapping flows. These CSVs provide no observed collector-arrival times.

The Thursday private file, `enp0s3-pvt-thursday.pcap_Flow.csv`, has no header. [audit_datasets.py](../../apt_benchmark/tabular_batch/audit_datasets.py) correctly reads all 4,114 rows using the verified 85-column reference header in memory. A default `read_csv` would lose its first data row and corrupt the schema. The existing combined CSV under `data/processed/dapt2020` adds file/day/network fields, but those fields are not native campaign IDs. Prefer the audited raw inputs when freezing D1.

The current 60/15/10/15 diagnostic lacks movement and exfiltration in fitting, and has only benign/movement in calibration. A whole-day held-out movement or exfiltration partition necessarily removes that stage's only date from training. Therefore distinguish **unseen-stage evaluation** from a closed-set temporal comparison. Do not fill missing class support by duplication, hidden future training, or favorable-cutoff searching.

**Eligible D1 use:** an explicitly scoped temporal ordering/support audit, and possibly a fixed supervised task on classes genuinely supported on both sides of a declared cutoff. A binary or unseen-stage rescope changes the research question and must be registered before fitting. Five-day uncertainty remains descriptive within this recording. No separate author holdout or redistribution license was qualified; keep raw data private. Prior DAPT detector/TTA work also means this source is already exposed development data.

Do not average DAPT and DSRL as two independent dataset replications or use DSRL to certify DAPT transfer.

## Why PX-082 cannot be copied unchanged

1. **Its prepared-data contract is specific.** [PX-082 run.py](../px082_temporal_audit/run.py) expects `current`, prior-only `history`, `start`, `end`, `capture`, `split`, `group_sha256` and four integer classes. These CSVs supply different native schemas and targets. Invented history, capture IDs or stage merges would change the experiment.
2. **Its paired arms need real ordering and supported training classes.** The past-only arm verifies every selected training flow ends before the earliest common-anchor event. SCVIC clocks are unqualified; DSRL attack chronology is generated; S-DAPT has no bytes; DAPT needs endpoint and support qualification. A timestamp parser alone does not satisfy that assertion.
3. **Its four-label mapping cannot be reused silently.** SCVIC has six native classes, DAPT/DSRL five. Preserve native targets, name the benign label explicitly, align model probability columns, and report unsupported-class metrics as undefined where appropriate. Missing stages must remain visible.
4. **Duplicate and grouping controls differ.** The existing numeric-feature audit finds 105,200 duplicate rows and one conflicting-label group in SCVIC; 12,673 duplicates and 337 conflicting-label groups in DAPT; 659 duplicates and no conflicting groups in DSRL. These are counts for the stated feature view, not complete raw-row duplication claims. Freeze treatment before splitting. Hash groups are not campaign clusters.
5. **The estimand must remain clear.** A common-anchor, matched-training-count comparison measures protocol sensitivity. A conventional random split changes the test population and cannot isolate future-information effects. Future training histories may also aggregate earlier anchor measurements even after current-feature duplicates are purged. Do not describe the entire difference as pure label leakage.
6. **The confidence unit cannot be copied.** PX-082's capture bootstrap was explicitly conditional on one campaign. None of these sources supplies verified independent campaign repetitions. Seeds, files and near-duplicate flows do not supply those missing independent units.

## Concrete next measurement gate

Freeze a dataset-specific adapter and eligibility result before model fitting: preserve source hashes and row IDs; retain native classes; exclude annotation/identifier shortcuts; record whether time means start, completion or arrival; report per-split native-class support; and verify duplicate disjointness on the exact intended predictor view. Publish unsupported arms as ineligible. An honest four-dataset qualification table is useful even when only a subset can support each experiment.
