# Pre-execution clarifications

The supplied PROTOCOL.md is preserved byte-for-byte. These details resolve implementation ambiguities without changing hypothesis thresholds. Both files are hashed before execution. Results are development evidence; H2 repeats a known result and is not a new prospective test.

1. **Fits:** exactly seven new final roles classifiers, seeds 8104–8110. Use the original capped training selection and original final training captures. Forward OOF fits in PX-081 trained selectors; no new selector is needed for this fixed OR rule. Repeating four forward fits per seed would violate the explicit seven-fit cap. No new forward-fold or current-only model fits are performed.
2. **Shared evidence:** one physical row has one acquisition outcome shared by all ensemble members. Use the existing seed-8101 availability/delay schedule for every member and comparator in each condition, chosen before replay. This avoids buying multiple independent acquisition attempts while charging one budget. Existing seed-specific results are not silently presented as this shared-schedule experiment.
3. **Fixed target experts:** current needs no extra evidence; roles requests only roles (cost 1); history requests only history (cost 2). A request is attempted only if affordable and within the nominal deadline; failed/late attempts still cost their full price. Failed acquisition falls back to the same seed's current model for original seeds. For new roles seeds, the default is the existing seed-8101 current model, explicitly a shared fallback; a user choice received before freeze supersedes this default. Mixed current/roles models share the one roles acquisition. No history is purchased by a roles-only member at budget 3.
4. **All-evidence reference:** A4 uses the full saved state-3 probabilities, charged cost 3, with availability bypassed and clearly labeled reference-only. It is not a feasible budget-1/2 policy or a delayed-availability result. It remains in descriptive H1/H6 checks, but not in H5. All deployable cells must satisfy per-row budgets. The audit separately checks the reference's explicit exception.
5. **Comparators:** UNRAVELED entropy and harm policies are independently replayed per original seed using their saved gains but the shared schedule. Record recovered and lost warnings against each named policy/seed, rather than choosing a favorable reference. AIT retains native saved always-history and entropy decisions for each seed.
6. **Oracle:** `best_single` selects the constituent with greatest exfiltration warning recall, breaking ties by fewer benign false alerts and then listed member order. It is a label-informed comparator, never a deployed selector. H1 separately compares OR with every member for every supported stage. H6 uses the exfiltration-best member, and is checked across all cells, including the 120 clean B2 triples and AIT pooled results. An absent stage or zero false-alert denominator is undefined, not a numerical zero.
7. **H3:** success requires strict recall improvement over the best seed in Wilson, Harrison and pooled, plus overlap below .75 in both executions. H4 non-decreasing recall is structural for nested OR sets; saturation and strictly decreasing overlap at the listed sizes are empirical. H5 is tested at each budget, with budget 2 primary. Wrong-host history cannot alter roles-only inputs and is a negative control, not evidence of robustness to roles corruption. H6 is reported as vacuous if no cell meets its antecedent.
8. **Costs:** report shared per-row acquisition cost separately from nominal ensemble member evaluations. Both OR and mean evaluate every member. Duplicate shared fallback evaluation may be cached; no measured wall-time speedup is claimed. AIT history cost is reported as one native history query and as two UNRAVELED-style cost units for accounting only; this is not a measured dollar cost.
9. **Subsets:** all 120 triples are evaluated on clean budget 2; nested sizes are evaluated in all requested conditions/budgets. Fixed class order is benign/other/movement/exfiltration for UNRAVELED, benign/other/exfiltration for AIT. OR stage refinement sums only warning members' non-benign probabilities using float64; mean also uses float64 and first-index tie breaking.
10. **Interpretation:** the rationale's broad statement about all threshold interventions is motivation, not a universal finding. Seed fits share attack examples and are not independent campaigns. Published OR semantics alone cannot establish novelty. No cloud or API calls are used.
