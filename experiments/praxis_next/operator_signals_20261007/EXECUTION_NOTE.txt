The initial S1 run completed105 fits and122 result rows under commit2f46972.
It was stopped before any S2 checkpoint to avoid repeatedly recomputing the
same expensive text features for each representation. No statistical design,
feature definition, partition, parameter, endpoint or negative result changed.

The optimized runner reuses deterministic features (also produced by S1A),
hoists mask/prefix feature extraction outside model loops, and supports
resuming the complete S1 checkpoint. Six models are refitted solely to restore
S2 inference state. Their labels AND score gaps must exactly match the original
checkpoint (absolute tolerance1e-12). These six reconstruction fits are separately
counted; they are not six new experiments. Normal from-scratch execution uses
the same optimized code without --resume-s1 and does not need checkpoint files.

The initial S1 warning list was not serialized before interruption; its contents
cannot be verified from the checkpoint. Subsequent and reconstruction warnings
are captured in RUN.json. Code at the original Git protocol commit preserves
the original execution definition.
After both S2 splits and the first S5 split completed, another checkpoint resume
reused identical prefix features across the10- and20-command eligibility cohorts.
Completed result and prediction rows were retained unchanged. This removes
redundant computation without changing prefix features or cohort definitions.
Warnings from pre-checkpoint phases were not serialized; RUN.json explicitly
marks warning capture incomplete. Interrupted, uncheckpointed computations are
not included in completed-study fit counts. No performance claim depends on
elapsed time. Wall time in RUN.json covers the last resumed phase, not the whole
research session. From-scratch execution captures all fit warnings normally.
