# Public datasets for APT-like behavior and attack-stage evaluation

**Review date: September 20, 2026.** Primary-source and artifact-access review by an AI research assistant; this is not a human label audit or evidence that a new method improves detection. No model was fitted in this review. Small author artifacts and metadata were inspected; the parent process separately acquired cAPTure's two reduced CSVs.

## Recommendation

Use **AIT-LDS exact source logs as the first runnable track**, conditionally qualify **cAPTure as the network-packet track**, and use **CasinoLimit only as an optional attack-stage/technique track**. AIT-ADS is an optional alert view of AIT-LDS, not an independent second dataset; its alert-to-source joins still need qualification. Compare all candidate models on exactly the same permitted inputs and splits within each track. These are different observation types and label definitions, so a single pooled leaderboard would be misleading. None supplies reliable real-world APT actor-attribution ground truth.

cAPTure has usable public bytes and temporal labels, but reduced-data construction and causal feature availability need further qualification. CasinoLimit has substantially more execution instances, but lacks realistic ordinary-user benign activity; it cannot establish operational false-positive rates. AIT-ADS has only eight emulated environments, so uncertainty must reflect that limited replication. See [benchmark design](BENCHMARK_DESIGN_REVIEW.md).

## cAPTure qualification: actual findings

### Access, schema and labeling

The reduced train/test files contain **1,529,050 / 1,043,911 packets**, including **622,920 / 543,105 attack-labeled rows**, according to the parent's full-file profiles. There are **25 potential input columns plus `phase_name`, `sequence_id`, `label`, and `timestamp`**. Acquisition hashes, all column names, small-file hashes and exact Drive IDs are in [capture metadata](../datasetmetadata/capture.json).

- `label` is the command/attack-step name; binary attack is `label != normal`.
- `phase_name` uses five author-defined phases: `RECONNAISSANCE`, `BRUTE_FORCE`, `DISCOVERY`, `INSTALLATION`, and `EXPLOIT`. These are not asserted to map one-to-one to all ATT&CK tactics. Missing phase on author-normal rows is expected, not an attack-stage label.
- `sequence_id` must stay a **string**: decimal-looking suffixes such as `.1` and `.11` are identifiers. Do not parse them as floats or infer independent campaigns from distinct IDs.
- Static processing code assigns command/phase labels using simulation start/end intervals, then removes `pause` and `discard`. This describes activity during a known emulation step; it does not independently prove that every packet in the interval is malicious.
- Composition code concatenates seven templates (`dollar_char`, `empty_conn`, `pub_exf`, `qos_mid`, `slash_char`, `sub_exf`, `user_prop`), shifting later timelines to follow previous ones. Normal traffic source days are separated by the author's train/test construction, but scenario templates recur. Reuse of source benign traces and template-specific shortcuts still need checking.

Actual reduced sequence metadata contains **1,365 training lists with 622,920 unique indices** and **861 test lists with 543,105 unique indices**. Index ranges are 17,239?1,508,657 and 5,694?1,028,775. These counts agree with the parent's attack-row totals, but this is not a completed per-row label/time join. Recompute chronological order from timestamps; do not assume numeric group order is time order. Primitive integer/list pickle opcodes were checked and class/persistent-object resolution disabled; arbitrary notebook/pickle code was not executed.

### Feature-selection audit

The actual 384,639-byte author notebook `0_feature_selection.ipynb` (Drive ID `1Hc7G0zXkwSuKGUUtURzcXzBEEuYDyNFG`, SHA256 `1455c32b410ea10a759602b551cdd785abc313bb7bb4c2d498a101d30d251e05`) performs constant/correlation filtering and **supervised mutual-information top-100 selection**. Its labels are filename-derived normal versus attack. The saved input listing contains **27 files: 25 named `_train_`, plus `normal_15_16_17` and `normal_2_3_4`**. No test-named file or test benign-day file appears. This supports train-only provenance for that notebook's selection; it does not establish the provenance of the released **25-feature reduced CSVs or their row reduction**. The listing includes `zero_len_train` source files, while the inspected final composition uses seven other templates. No test-label feature-selection leak was demonstrated by this inspection, and the remaining transformation is not proven clean.

### What a fair first comparison may claim

Use a frozen conservative feature view. Keep the four target/group/clock columns out of the estimator. Quarantine TCP `completeness` and all selected `tcp.analysis` fields until packet-prefix replay demonstrates when each value becomes available. Some analysis fields may be causal, but this review did not establish that. Exclude direct MAC/payload and sequence/message identifiers from the primary view to reduce construction shortcuts. Fit encoders, scalers and any further feature selection using training data only.

The reduced corpus supports a **retrospective public-artifact comparison** once the above scope is explicit. A strict live early-warning claim additionally requires causal feature validation, timestamp/step joins, no future-derived aggregation, and resolution or explicit bounding of the reduced-data provenance. The paper already evaluates latency versus FPR and publishes timing-jitter variants using [HOWLATE](https://github.com/TommasoPuccetti/howlate); simply comparing models on those metrics is not a new methodological contribution.

## CasinoLimit qualification: stage-only track

[Machine-readable access receipt](../datasetmetadata/casinolimit.json) pins Zenodo version **17256954** and author GitLab commit **bc75bd5f8640c2b698577c139111c861f90a0082**. Public archives include `output.zip` (1.89 MB), `syslogs_labels.zip` (19.75 MB), `cache.zip` (49.43 MB), `labelled_flows.zip` (851.01 MB), `flows_zeek.zip` (1.11 GB), and `syslogs.zip` (1.67 GB). The PCAP route is request-only; no PCAP access was assumed.

The inspected `output.zip` contains **114 nonempty system-label instances, 9,243 label objects and 66 technique identifiers**. Labels link auditd event IDs to ATT&CK techniques. These counts are neither independent events nor independent campaigns. Public network features include timestamp, duration, endpoints, ports, byte/packet counts and protocol, plus annotation-derived `labels` and host-derived `proctitles`. Exclude `labels`; using `proctitles` changes the task to fused host/network evidence. Process-aggregated cache records may include future observations and are unsuitable for a prefix experiment without reconstruction.

The author milestone manifest has 140 provisioned instances. All 114 labeled instances join it, but milestone coverage is **113 initial logins, 66 meeting-camera logins, 49 bastion logins, 46 bastion-root events and 10 flags**. One labeled run lacks the initial milestone; retain unknown/censoring. Missing downstream milestones are not proof of benign activity. README prose mentions UTC+1 while actual milestone strings carry `+02:00`; validate epoch/time joins rather than applying a guessed offset.

Hold out whole execution instances. Some instances belong to the same attacker restarting, so instance-disjoint splitting alone does not ensure actor-disjoint generalization. The datasheet expressly lacks realistic benign user activity. The defensible target is **recognizing technique/stage in held-out executions of this challenge**, with late-stage uncertainty reported; it is not real-world APT attribution or operational false-positive suppression.

Private evidence: `research/casino_output.zip`, `casino_steps.csv`, `casino_README.md`, `casino_datasheet.pdf`, `casino_record.json`, and `casino_commit.json`. All exact hashes are in the metadata receipt.

## Names and dates that should not be overstated

- **DARPA TC and original OpTC** are older collections reused by recent methods such as MAGIC and KAIROS. A 2024 detector paper does not make those datasets newly released in 2024.
- **PWNJUTSU** is a real **2022** dataset, [IEEE TNSM DOI 10.1109/TNSM.2022.3183476](https://doi.org/10.1109/TNSM.2022.3183476), with an [official public directory](https://pwnjutsu.irisa.fr/dataset/). Its roughly 82 GB compressed artifact and explicit license/event-ground-truth details were not fully qualified here.
- **LMD-2023** is real: [author collections](https://github.com/ChristosSmiliotopoulos/Lateral-Movement-Dataset--LMD_Collections), [2023 paper DOI 10.1007/s10207-023-00725-8](https://doi.org/10.1007/s10207-023-00725-8). A [2025 reuse paper](https://doi.org/10.1016/j.cose.2024.104190) is not evidence for a newly released ?LMD-2025.? No exact primary match for that name was verified.
- ?APT2025? alone is ambiguous. **Windows-APT2025** is verified above; do not substitute an invented dataset or assume its paper name is the collection year.

## Implications for a praxis contribution

There is a useful benchmark-building task here, but **a new benchmark result is not by itself a novel method or a positive experiment**. Stage estimation is already studied by [TREC, CCS 2024](https://doi.org/10.1145/3658644.3690221), and the March 2026 preprint [Learning the APT Kill Chain](https://arxiv.org/abs/2603.07560) combines temporal reasoning with provenance data; the author v2 record now reports acceptance to IEEE GLOBECOM 2026, although a publisher proceedings entry was not independently verified (rechecked September 20, 2026). The cAPTure paper already covers latency/FPR. A candidate contribution must therefore name and test a narrower improvement, such as reliable causal-prefix stage decisions under held-out execution or sensor changes, against those nearest methods. Whether it improves performance remains unmeasured.

This review establishes availability and limitations. It does not supply a successful detector, prove dataset-label correctness, certify false-negative risk, or establish real-world actor identification.
