# Design review: a causal benchmark for earlier malicious-behavior detection

**Review date: September 20, 2026. Status: proposed design, no model results.**

## Recommendation

Build one reproducible evaluation environment and qualify one dataset before adding a second or third. Compare algorithms on the same observable event history, labels and held-out episodes. Treat the environment as research infrastructure; a model leaderboard or replacing a graph network with Qwen is not, by itself, a defensible novelty claim.

Keep three questions separate: **Is malicious behavior present now? Which documented behavior or stage is present? Was an episode detected before a documented impact?** Detecting a withheld attack family is not identifying its actor, proving a zero-day exploit, or attributing an APT group. The dataset must establish any actor labels used for an additional attribution task.

## Minimum data contract and fair comparisons

1. **One canonical event contract:** source record ID, event timestamp, availability timestamp if recorded, host/entity/session identifiers, event type and allowed attributes. Store labels and episode/stage annotations separately. Preserve source hashes and parser version. If only event time exists, label replay as an idealized zero-ingestion-delay experiment; a later injected delay is a simulation, not a measured collection delay.
2. **One causal prediction unit:** for example, a host at the end of a fixed trailing window. All models receive transformations of the same raw records available by that time. Classical models receive counts/statistics; TCN/Transformer receives ordered events; GraphSAGE/GAT receives the prefix graph; TGN updates state incrementally. Graph edges must express documented relations, not arbitrary k-nearest-neighbor links presented as causality. A relational model on a flow-only dataset is a different track if the graph has no source-supported entity relations.
3. **Equal information does not mean identical tensors.** Use a shared event/attribute/history budget and include a no-history model, counts-only model, last-event model and train-only lexical novelty baseline. Report native-system reproductions separately because their input and label assumptions may differ.
4. **Separate supervision tracks.** Supervised logistic regression, random forest, XGBoost, TCN, Transformer and GNNs may share the same labeled fit set. Benign-only anomaly models are a separate matched-supervision comparison. A model trained with malicious examples cannot establish superiority from architecture alone over one forbidden those examples. Include an isolation-forest or comparable simple anomaly control there.
5. **Four roles:** fit representations and preprocessing; select hyperparameters on development episodes; calibrate the fixed alert policy on separate pre-test data; evaluate once on held-out episodes/time. Keep whole source episodes, exact/near-duplicate families and overlapping windows together. Purge overlap according to maximum history and label horizon. Do not force a temporal/entity-disjoint split if the available data cannot support one; declare the unsupported claim instead.
6. **Two distinct generalization tests:** forward-in-time on known environments, and held-out scenario/attack-family or host/environment where enough independent groups exist. Same hosts across time can be appropriate to the first, not evidence for the second. A giant connected component may make the requested split infeasible; do not break it to manufacture sample size. Fit vocabularies/scalers only on fit data; define cold-start and permitted unlabeled streaming state updates prospectively.
7. **Bound search cost:** same declared candidate count or tuning resource cap per family, fixed seeds, development-only checkpoint selection and all completed seeds reported. Record parsing, preprocessing, inference, memory and queueing costs separately. An unavailable package or failed run is an engineering result, not a low F1. Optional Qwen needs a pinned revision/prompt, deterministic decoding and an independently qualified context/output budget; malformed or timed-out responses remain explicit failures/abstentions. Pretraining exposure to public benchmarks is unknown.

## Early and stage labels without hindsight leakage

- Define episode onset as the first source-supported malicious action in the available telemetry. A process eventually used maliciously is not automatically malicious at every earlier timestamp. Entity-level end-of-capture labels cannot support event-level onset claims without additional annotation.
- Define impact separately from the original scenario evidence, such as the first documented exfiltration or destructive action. If impact is absent or ambiguous, report it missing; do not set it equal to the last record. Some episodes may offer no observable pre-impact opportunity, which must be reported.
- Earliest detection is the first correctly attributable alarm **as available to the operator**, after onset. Its time includes feature availability, window completion, score computation and configured queueing. A retrospective alarm reconstructed using later events receives the later availability time.
- Measure detection before impact and the cumulative fraction of all episodes detected by fixed delays. Retain missed episodes as right-censored observations. A median over only detected episodes can look better when difficult attacks are missed; it is not the primary delay metric. A simple all-episode restricted mean requires a common fully observed horizon; otherwise return undefined or use a separately justified survival estimator.
- Stage identification requires a versioned source-to-stage map with evidence and an explicit unknown/ambiguous category. MITRE ATT&CK tactics can overlap and are not a universal chronological chain. Use multilabel targets where warranted. Do not map generic attack names or classifier predictions into supposed ground truth. Report each stage's support and one-vs-rest metrics; a stage absent from test has undefined recall/AUC.
- A completed flow's final duration, final bytes, packet totals, backward packets and end state become available at flow completion. They cannot be used for a prediction claimed at flow start. Prefix-flow features require original packets or another verifiable incremental source. On completed-flow CSVs, report post-flow detection, not pre-impact early detection.

## Metrics and attainable decisions

Primary operational comparison: episode detection before documented impact **at a frozen benign-host-hour alert budget**, with the same cooldown/deduplication policy. Actual benign exposure must come from qualified observation intervals; event minimum/maximum timestamps alone do not prove continuous monitored time. State whether the budget is a calibration target or an observed test result. Event false-positive rate is a different quantity.

Report precision, recall, F1, balanced accuracy, MCC, continuous-score ROC-AUC and average precision, with prevalence, confusion counts and undefined cases. Average precision is not a trapezoidal PR-area synonym. Include per-stage and per-episode/scenario tables; show pooled row-weighted and equal-group macro metrics separately. Average per-dataset results explicitly rather than silently pooling different targets. Bootstrap source episodes or host-days only when their dependence assumptions are defensible; thousands of rows or repeated seeds do not create independent campaigns. With very few episodes, report exact counts and descriptive sensitivity rather than confident population intervals.

Before selecting a practical criterion, check its mathematical attainability: a baseline at 98% recall cannot be improved by five percentage points; a zero false-alarm rate cannot be reduced by a positive absolute amount. Predefine a finite family of useful routes, such as accuracy superiority at a common budget **or** accuracy noninferiority with materially lower latency/cost. Select the primary comparison on development data and freeze it. If a test baseline reaches the ceiling, report the absolute-gain route as uninformative/unattainable; do not silently revise it or declare scientific failure from that criterion alone. Include a no-op candidate that exactly reproduces the baseline to test that improvements are not invented.

## Three conditional mechanism candidates

These are hypotheses worth screening only after the benchmark works, not established novel contributions.

1. **Arrival-aware memory for delayed or missing telemetry.** Maintain bounded causal state keyed by observed entity identity and track whether a relation is absent or merely not yet available; delayed events may update subsequent decisions but may not rewrite earlier alarms. Compare against the same TGN/sequence model with ordinary arrival-order updates, a lateness buffer, missingness indicators and dropout augmentation. Use equal histories, memory and alarm budgets. The narrow question is whether this handling preserves pre-impact recall under held-out channel outages or delay bursts without degrading clean operation. Kairos/Orthrus and generic robust learning are close prior work; source timestamps alone permit only simulated delay claims.
2. **Deadline-sensitive escalation from a cheap detector to richer context.** A fixed selector estimates the expected incremental detection benefit per unit of compute from past visible evidence, deciding whether to invoke a graph/sequence model before the next decision deadline. Train selection out of fold; never pass true stage or future impact time into the selector. Compare always-cheap, always-expensive, random allocation, uncertainty allocation and a standard budgeted router under identical total work and latency. GridPRISM is direct overlap: a defensible contribution would require demonstrating a distinct mechanism for deadline-aware escalation and an attainable early-detection benefit, not merely adding a budget switch.
3. **Identifier-stable prefix representation under held-out environments.** Separate typed actions/relations from opaque identifier strings and enforce consistency under semantics-preserving renaming of private identifiers while retaining discriminative command or operation content. Compare simple canonicalization, lexical allowlists, the unmodified encoder and ordinary augmentation. Renaming must preserve entity equality and relations and must not delete the attack-defining payload. Evaluate a real held-out environment in addition to synthetic renaming. Existing semantic encoders, augmentation and the 2026 lexical-shortcut analysis create substantial overlap; only a precise, useful mechanism that beats these controls could justify further novelty work.

## Required qualification tests before a real run

- Appending or changing future records cannot change earlier features, scores or alarm availability; future-only metadata and final-flow counters are rejected by early adapters.
- Shuffling equal-time input order follows a documented deterministic policy; TGN scores before any prohibited future update, and test/episode state cannot leak backward into training or another episode.
- Exact/normalized duplicates, common episode IDs and overlapping input windows cannot cross forbidden split boundaries. A source entity label must not silently become a malicious label for its entire earlier lifetime.
- Unseen categories and missing stages are handled explicitly; a supplied stage name does not imply temporal order or make a missing stage annotation valid.
- Fit-only scaler/vocabulary hashes, fixed operating thresholds and shared unit IDs are checked. ROC-AUC and AP consume scores, not thresholded predictions.
- Ceiling/floor checks detect impossible superiority criteria; ties, all-positive/all-negative labels, no alarms, no benign exposure and zero pre-impact opportunity have explicit outcomes.
- Missed attacks remain in all-episode summaries; insufficient follow-up cannot be imputed as a fully observed miss at a longer horizon.
- Compute includes the context-building and routing overhead. A future-aware oracle, if shown, is descriptive and cannot choose the final model or threshold.

**Finite first milestone:** qualify data and temporal semantics, reproduce strong simple baselines, then compare one representative sequence and one representative graph model on the same supported target. Add remaining architectures only after this comparison passes the leakage and metric tests. A valid negative comparison is a completed result; it must not trigger an endless search for a positive score.
