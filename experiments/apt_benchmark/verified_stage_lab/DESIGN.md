# Fresh verified-outcome lab: complete a bounded mechanism test

September 22, 2026. Freeze this source and collection/model protocol before the 48-block run. Prior one-block collector integration tests are software tests, not scientific evidence.

## What completion means

Collect 2,304 new current transactions and their preceding transactions, verify actual outcomes, run the fixed comparisons, independently audit artifacts and metrics, and publish every test condition. This completes a controlled mechanism experiment. It does not repair the old Windows timestamps or complete a claim of real-world APT detection. [The final old-data clock review](../host_auth_context/CLOCK_RECOVERY_FINAL.md) closes that recovery route.

Three distinct worker processes perform actual loopback HTTP requests through one fixed endpoint. One worker dispatches a bounded request to another. Allowed operations are a fixed hash computation and receipt of a generated dummy object. There is no arbitrary command execution, exploitation, persistence, external target or real confidential data. All three workers run the same software on the same OS; their logical role tags are metadata, not independently administered enterprise hosts.

## Independent outcome verification

Requested operations do not determine the label. The controller independently rereads a computation artifact and verifies the expected hash, or rereads the received object and checks bytes and SHA-256. Labels are neither, remote action only, file transfer only, or both. Authentication denial and operation failure remain in the denominator. Failed transfers create an intentionally partial object that must not be counted as complete. Worker receipts, nonces, paths, payload strings, requested masks and failure-mode fields never enter predictors.

This verifies harmless remote-action and transfer analogues. It does not establish an unauthorized host compromise or theft. A later intent diagnostic applies opposite hidden policy interpretations to the same technical vector. Those are counterfactual interpretations, not additional physical executions or independent campaigns. With that policy withheld, any deterministic classifier must be correct for exactly one of each opposite-label pair. A model cannot infer information deliberately absent from all of its observations.

## Fully crossed collection and fixed partitions

Each of 48 blocks contains all **4 prior-operation masks × 4 requested-current masks × 3 outcome modes**, in randomized order. Source/destination pair and dummy size are randomized independently. Every worker pair can perform every operation. Payload sizes overlap, request formats have equal length per payload bucket, replies have a fixed length, and every outcome uses the same endpoint. Ordinary HTTP status is an allowed current observation; it identifies a reported failure, not which operation succeeded.

The first 24 blocks are fitting, the next 8 calibration, and the last 16 test. No packet, record, augmented view or episode from a test block enters fitting. Each transaction has nonce-isolated artifacts. Workers persist; these are repeated executions within one generator and OS, not unrelated campaigns.

Fitting/calibration use the **linked subset**, where the preceding requested operation matches the current one. This deliberately creates a predictable workflow: a positive score here is a mechanism/shortcut demonstration, not evidence of natural attack-stage correlation. The test is always reported three ways:

| Population | Definition | Expected current transactions |
|---|---|---:|
| Linked test | Earlier and current requested operations match | 192 |
| Crossed-history stress | Earlier and current requested operations differ | 576 |
| Complete factorial test | All test transactions; includes both groups above | 768 |

The complete factorial test makes earlier and current requested operations independent by construction. The crossed group is a deliberate history-mismatch stress test, not a representative enterprise distribution. The overlapping test tables must not be added together as new samples.

## Observable information and time

The feature builder accepts only FLOW and TELEMETRY streams. It does not accept truth records. Primary current features contain request/response **body** byte counts, HTTP status, and shared prior-record availability/count/channel indicators. They are not packet-capture measurements. Six primary arms exclude elapsed time so trivial RPC implementation speed does not create a headline result. A seventh timing diagnostic is reported separately.

Prior features summarize the four instrumented event types: authentication, remote job, file write and request end, using counts, successful-event counts and byte totals. Only the corresponding episode's preceding RPC contributes. Both event time and actual controller receipt time must precede the current RPC's start. Parent/child RPC time bounds are checked using the same-OS performance-counter clock. These instrumented application events are not Windows Security, kernel audit, or production SIEM logs.

The wrong-source control uses the earlier available history snapshot of a completed transaction from a different source in the same block. Its existence indicator is supplied to all arms. It is a correspondence control, not an independent real host-history distribution.

Test conditions are clean observation, removal of prior remote-job records, removal of prior file-write records, a synthetic 50 ms addition to prior collector-arrival time, and permutation of logical role labels. The role permutation changes metadata on the same executions; it is not physical network-domain generalization. History drop/delay rules are fixed independently of labels. Models fit clean observations only; no results select a favorable censoring amount.

## Fixed comparisons and interpretation

Seven LightGBM views use the same 288 linked fitting transactions and fixed parameters: current observations, current+roles, current+history, current+roles+history, current+roles+wrong history, history/availability only, and an explicitly separate timing diagnostic. Use three seeds, 100 trees, 7 leaves, depth 3, learning rate .05 and minimum child count 5. These seeds reuse the same rows and need not change predictions; they are not independent scientific replications. There is no hyperparameter search.

Compare with majority prediction and a simple rule: use earlier successful remote/file evidence when the current RPC reports success, otherwise predict neither. The rule may solve the deliberately linked workflow. An ML model cannot claim novelty for rediscovering it.

Publish four-class confusion/precision/recall/F1 and macro-F1; remote-action and transfer binary precision/recall/F1/AP/ROC; and the same metrics restricted to current HTTP-200 cases. This restriction prevents abundant failed/no-outcome cases from making overall accuracy appear stronger than operation discrimination. Calibration observations are reserved and scored but do not select a new threshold or model. Both-label truth is supported, not forced into a single attack stage.

Do not turn a completed transfer into “theft,” a remote computation into “compromise,” or a linked-workflow score into field effectiveness. The [literature review](LITERATURE_SCOPE.md) supports the need for benign lookalikes, preceding-context evaluation and outcome verification, while documenting that all these broad ideas have prior art. This run cannot establish algorithm novelty or replace independent enterprise evidence.
