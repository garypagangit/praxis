DEVELOPMENT PILOT v1 -- PRE-OUTCOME SPECIFICATION

Research question
At comparable feedback opportunities, do runtime AI and genuine human operators
differ in selection, transformation, verification or correction in ways not
explained by commands alone or prior error/repetition features?

Collection target (planning choice, NOT power calculation)
H: eight consenting people x four tasks = 32 sessions.
A: two model/controller configurations x four independent fresh sessions per task
   = 32 sessions. Repeated generations are NOT eight independent models/operators.
S challenge: two independently documented non-AI-authored deterministic policies
   x four tasks = eight sessions. Do not count AI-written policies as pure S.
Total planned: 72 sessions. If S cannot be obtained, retain a bounded H/A pilot
and explicitly defer automation specificity. M/hybrid is deferred, not mislabeled.
No participants are currently arranged. Do not generate substitute human traces.

Assignment
Each human performs each template once, after the same unscored practice task.
Counterbalance template order using four cyclic orders, two humans per order.
Assign variant seeds 101, 202, 303, 404 twice per human task; each AI configuration
uses all four seeds once per task. Keep same template/variant environment across
origins. Do not let the same human see two variants of the same scored template.
Fresh process/state per session. Distinct session ID, no cross-session AI memory.
Scripts use the same tool interface and task budget. Task-family or variant names
are not shown to operators; instructions and help text are identical across arms.
Document skill/experience separately; humans can use ordinary reasoning but no
external AI, internet assistance or shared solutions during scored sessions.

Observation and origin
Common serial recorder: exact accepted command, returned text, exit code, truncation
and times. Use only five completed submissions for the primary prefix. Report
coverage including short sessions, timeouts, failures and uncertain provenance.
Ground truth is controller identity plus human attestation and operator supervision;
runtime provider records verify AI control. Keep it separate from input features.
The provenance template records interventions and offline AI assistance. Any
discretionary intervention in A makes it mixed/unknown for the affected prefix.
Do not give operators the target source, seeds, answer key, or research hypothesis.
Do not expose operator category in prompt wording. All receive OPERATOR_BRIEF.txt.
The researcher owns the target process; only text command/result exchange is exposed.

Primary pilot outputs
1. Capture completeness, prefix coverage, opportunity counts and annotation agreement.
2. Per-person/configuration and per-template rates of the four codebook responses.
3. Task-balanced AI-minus-human contrasts, with every individual/session displayed
   in the internal analysis; no treating transitions as independent participants.
No fitted detector, significance fishing, optimized cutoff or operational accuracy
claim is required at this stage. All four candidate responses must be reported.
Direction is exploratory; use new held-out data to confirm a selected direction.
An absence of statistical significance in this small pilot does not reject a small
effect. The decision rule screens feasibility and consistency, not proof.

Confounds to record before interpreting a difference
Available feedback, number of accepted actions, output length, action type, task
success, human experience, operator/configuration, task order and task variant.
Success is evaluation-only, never a feature. Common target removes source-format
confounds but the restricted action vocabulary can suppress or induce differences.
If both arms follow the same short deterministic recipe, this task pack has a
ceiling/floor problem; it cannot support a claim of no difference on real attacks.

Progression to confirmation
Use pilot variation and eligible independent-unit counts to plan precision/sample
size for a chosen practically useful effect. Freeze task, actor and configuration
splits; new tasks must differ structurally, not just rename literals. Compare
commands-only, opportunity-only, prior error features and added validated response
patterns on identical sessions. Calibrate thresholds only on calibration data.
Report human and script false flags, AI recall, abstention/coverage and clustered
uncertainty. Modest credible improvements count. Confirmation requires adequate
new human operators and held-out attack environments; two AI models cannot establish
generalization to all AI. Analyst benefit then needs a separate decision/time study.
